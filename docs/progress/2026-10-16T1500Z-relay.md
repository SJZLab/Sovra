## CI-red follow-up on PR #866 (same shift, after the `check_run.completed` webhook)

The `gate` check failed at step 11 "Python lint + format + type check (FTF-0002)" on head
`32ea3bec`. Fetched the job log (`mcp__github__get_job_logs`, job 117019645449) rather than
guessing: `ruff check`/`ruff format --check` both passed; `mypy .` (run repo-wide, 555 source
files -- the local per-file check during development only ever covered this round's six
declared files, never the whole repo) found 2 real errors, both in
`tests/integration/test_ftf_h011_p1_mapping_preview_postgres_s3.py` (lines 433, 509):
`No overload variant of "__getitem__" of "tuple" matches argument type "str"`.

Root cause: this PR's own earlier edit removed 3 `# type: ignore` comments from that file as
"now-redundant" (believed covered by the file's `# mypy: disable-error-code=...` line). Two of
the three were not redundant -- they guarded `call-overload`, a code the disable-error-code line
never listed (it listed `index`, a different mypy error code for a different shape of the same
union type). This PR's own fault, not a pre-existing/base-branch failure; no revert-and-port
needed, no standing-down comment needed (Section "CI red": fix and push when the failure is in
code the PR touches).

Fix: added `call-overload` to the file's disable-error-code set. The single-line form put the
comment over ruff's 100-char E501 limit; a trailing `# noqa: E501` broke mypy's own directive
parsing (confirmed by a throwaway repro in `/tmp` -- mypy treated the whole `# noqa: E501` tail
as part of the error-code list and rejected it as an invalid code, which would have *reintroduced*
the same CI failure under a different error message). Verified instead that mypy merges multiple
`# mypy: disable-error-code=...` comment lines in one file (same throwaway repro), and split the
directive across two lines, each under the line-length limit. Re-ran `ruff check .`,
`ruff format --check .`, and `mypy .` repo-wide after the fix: all three clean, 555 files. Pushed
as `2a82b223` on the same `relay/FTF-H011-P1-r2` branch/PR #866 (no new branch, no new PR -- this
is drive-to-green on a PR this shift opened, not a new item).

Lesson for next time this file's touched: run `mypy .` (whole repo), not `mypy <touched files>`,
before pushing -- a file-level suppression comment can silently fail to cover every mypy error
code a change triggers, and the gap only shows up at the whole-repo scope CI actually runs at.
