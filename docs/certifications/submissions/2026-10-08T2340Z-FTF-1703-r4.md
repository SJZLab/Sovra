## Control-plane ask (QUEUE.md "0g", docs/certifications/queue.md 2026-10-08T22:02Z return)

Verifier findings (a9c802c, #654: round-3 P-A, P-B and G4 fixed; mutation 73/73). Required:

1. No method calls or field reads on caller input: a frozen dataclass has no `__slots__`, so
   `object.__setattr__(t, "to_dict", ...)` on an exact-type `TrainingTrace` shadows the method.
   `verify_trace_provenance` and `_scan_secrets` call `trace.to_dict()`; `_check_reserved` calls
   `trace.final_answer()` and reads caller fields. Reproduced: a trace carrying a sealed prompt and
   an `sk-` key passed provenance and the secret scan (P4); a trace admitted despite overlapping the
   sealed final suite (P5, held-out leakage). Refuse a trace whose instance `__dict__` has keys
   beyond the dataclass fields, compare provenance field by field, and run the reserved check,
   secret scan and replay on the regenerated object.
2. Admit each generator index at most once, under its own id (P6).
3. Exact types in `_validate_review` (`type(review) is ReviewDecision`, plain `str` fields): a str
   subclass with `strip()` overridden let `GENERATOR_ID` review (P8); a decision whose `__eq__` is
   always `True` let a conflicting review pass unnoticed (P8b).
4. spec-matrix notes and evidence_hash updated to round 4.

## What changed

**Production** (`evals/reference/training_dataset.py`):

- `_TRACE_FIELD_NAMES` (the dataclass's own declared field names) and a check in
  `_require_trace_shape`: `set(vars(trace)) != _TRACE_FIELD_NAMES` is refused unconditionally —
  catches any instance carrying an attribute beyond its declared fields, whether or not it would
  currently lie about anything.
- `_raw_trace_dict(trace)`/`_raw_final_answer(trace)`: every field read by direct attribute access,
  never a method call. `verify_trace_provenance` now compares `_raw_trace_dict(trace)` (not
  `trace.to_dict()`) against the regenerated reference; `_scan_secrets`/`_check_reserved`/
  `verify_trace_replay` use the same helpers instead of `.to_dict()`/`.final_answer()`.
- `build_training_dataset`'s per-trace loop: first pass unchanged in order (`_scan_secrets` →
  `_check_reserved` → `verify_trace_provenance`, now all shadow-proof via the helpers above, so
  every existing test's specific expected error — `SecretInTraceError`, `HeldOutLeakageError` —
  still fires exactly as before); then an explicit `seen_indices` set refuses a second trace
  claiming an already-admitted `provenance["index"]`; then a **second pass**, defense in depth, re-
  runs `_scan_secrets`/`_check_reserved`/`verify_trace_replay` on the freshly regenerated object
  (never caller-touched), satisfying the ask's literal "run … on the regenerated object" without
  changing any existing test's observable behavior (any trace reaching this point has already been
  proven field-for-field identical to that regenerated object).
- `_validate_review`: `type(review) is not ReviewDecision` (was `isinstance`) and
  `type(value) is not str` (was `isinstance`) for `trace_id`/`reviewer_id`/`decision`.

**Tests** (`tests/reference/test_ftf_1703.py`), three new functions, no existing test changed:

- `test_round4_instance_attribute_shadowing_is_refused` — builds a genuine trace, tampers its real
  `steps` to carry a secret, then `object.__setattr__`s `to_dict`/`final_answer` to lie and report
  the original clean content. Confirms the shadow is refused outright, isolates that even a
  *non-lying* shadow (identical content) is refused by the `__dict__` guard alone (content-
  independent), and — with that guard disabled — confirms `verify_trace_provenance` *still* refuses
  the lie via direct field access, while an old-style (`trace.to_dict()`-based) comparison would not.
- `test_round4_each_generator_index_admitted_at_most_once` — with `verify_trace_provenance` patched
  to accept anything (isolating the index guard from the check that would otherwise also catch this),
  two ids claiming the same index are refused to exactly one admission; two genuinely distinct
  indices are both admitted.
- `test_round4_review_decision_requires_exact_types` — a `str` subclass reviewer_id whose own
  `strip()` lies, and a `str` subclass decision whose own `__eq__` always returns `True`, are both
  refused outright; with the exact-type guard replaced by the pre-round-4 `isinstance` check, both
  attacks succeed instead.

## Existing-test compatibility

All pre-existing tests pass **unchanged** — in particular the three that expect
`SecretInTraceError` for a secret injected into a trace's steps (`test_no_harvest_no_secrets`'s loop,
and the dict-key/nested-key variants): `_scan_secrets` keeps its original position (first pass, on
the caller's own trace) and is now safe via `_raw_trace_dict`, so tampered content is still refused
with its own specific error before the more generic provenance mismatch would otherwise fire first.

## Same-class sweep

The defect class is "a frozen dataclass instance can have a bound method shadowed via
`object.__setattr__`, and a verification path trusts that method on untrusted input." Searched
every `frozen=True` dataclass under `evals/`, `packages/`, `apps/api/app/`, `workers/` for a
`to_dict`/similar method also called on caller-supplied instances: only `training_dataset.py`'s own
`TrainingTrace` has this shape. No sibling module needs the same fix.
