## Production change
- **`memberships` (migration 0021, chains onto 0020).** `organization_id` FK, nullable `workspace_id` with composite FK
  `(organization_id, workspace_id) -> workspaces(organization_id, id)`, `issuer`/`subject` (FTF-0101's identity),
  six-role CHECK, `active|revoked` CHECK, `UNIQUE ... NULLS NOT DISTINCT` (covers the NULL-workspace case). ENABLE +
  FORCE RLS. `tenant_isolation` (FOR ALL, USING + WITH CHECK on the transaction-local organization) and a SELECT-only
  `identity_self_lookup` policy that admits a row only when BOTH `app.current_issuer` and `app.current_subject` are bound
  to that row's own identity (this is what lets the login-time lookup run before any organization is known without
  exposing anyone else's rows). `sovra_app` is granted SELECT only; writes go through the operator CLI under the
  migrate role.
- **`membership_store.py`.** `lookup_org_role` reads only ACTIVE, ORGANIZATION-level rows (`workspace_id IS NULL`) under
  the path organization's tenant context; revoked, workspace-level, foreign and unknown identities all give `None`
  (403). `lookup_membership_status` is the login gate (ACTIVE / REVOKED / UNKNOWN). A DB error propagates (Law 17),
  never reads as a grant or as "no membership". Content-free `sovra.auth.decision` events (outcome, reason code,
  organization id, request id; no subject, issuer or cookie).
- **`session_principal.py`.** `SessionPrincipalResolver` reads only FTF-0101's signed session cookie: signature, age,
  well-formed claims, revocation. Nothing in a header, query or body can supply an identity.
- **`main.py`.** One real resolver and one real role lookup passed to all 20 routers; the login router gets the real
  `membership_lookup` and the SAME `SessionRevocationStore`, so `/auth/logout` revokes the session for the API too.
- **CLI.** `python -m app.auth.membership_admin_cli grant|revoke` (migrate role, `SOVRA_DATABASE_URL`).

## Disclosures
- The revocation store remains in-memory per process (FTF-0101's disclosed limitation, unchanged): after a logout on
  one API instance another instance still honours the cookie until it expires. A shared store is a separate item.
- Role changes take effect on the very next request of an existing session (role is read per request, by design);
  a revoked membership is denied immediately even on a live session.
- No new runtime dependency; no public membership-write route (operator CLI only, per the contract).
- The CI job `live-auth-path-integration` was written against the same pinned postgres image pattern as the other
  integration jobs but could not be run in the sandbox (no container-registry egress); the same test was run locally
  against PostgreSQL 16.15 installed directly. This PR touches `.github/workflows/ci.yml` (new step + new job only),
  as every task that adds a CI job does; flagging in case Control plane wants it handled as `[GOVERNANCE]`.
