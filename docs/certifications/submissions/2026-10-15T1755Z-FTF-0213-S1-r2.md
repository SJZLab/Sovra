## Items

1. **V16-LATER-TRIAL-400.** The main loop already returns immediately on any non-200/400
   status, so a later-trial 400 could never actually continue the loop in the shipped code —
   but nothing pinned the exact request count, and `_aggregate_trials` (only ever called with
   `len(trials) == _TRIALS` by construction) had no defensive check of its own. Added: a new
   `mid_run_reject` gateway mode (trial 1 succeeds, every later trial is rejected) plus
   `test_mid_run_400_stops_after_exactly_two_requests`, pinning `UNSUPPORTED_PARAMETER` with
   exactly 2 requests made and only 1 trial's result kept. Added a defensive
   `if len(trials) != _TRIALS: raise ValueError(...)` at the top of `_aggregate_trials`, with
   `test_aggregate_requires_exactly_trials_count` (0, 1, 2, 4 trials each refused; exactly
   `_TRIALS` accepted).
2. **V18-PARTIAL-USAGE-MAX.** Confirmed production already correct (`all_usage` already
   requires every trial's `completion_tokens` to be present), but no test exercised *partial*
   usage (one trial missing, others present) distinctly from the existing all-missing case.
   Added two checks pinning that a single missing-usage trial still reports
   `max_completion_tokens_observed is None` and `mean_completion_tokens is None` (not an
   average of the other two).
3. **USAGE-IMPOSSIBLE-COUNT (production bug, Law 11/17).** By the point usage is checked,
   every trial has already proven `label_in_enum` and `finish_reason == "stop"` — a real,
   non-empty, enum-matching answer. A reported `completion_tokens` of `-5` or `0` for such an
   answer is a gateway lie, not a real cheap-output metric; the old code accepted it as
   `CONSTRAINED_OBSERVED` with that count verbatim (the removed
   `"zero tokens is a real count, not missing"` pin proved it). Fixed: negative counts refuse
   as `MALFORMED_RESPONSE`; a zero count folds into the existing `USAGE_MISSING` path (next
   item) rather than a fake success.
   - **Law 1 evidence (shown able to fail against the pre-fix module):** `git stash` the
     production fix alone, re-run — 9 of the new/changed checks go RED (negative-count checks,
     zero-count-is-USAGE_MISSING and its None-max/mean checks, the exact-trial-count guard for
     1/2/4 trials); `git stash pop` restores all green. Full output in this repo's shift log.
4. **Equivalent-mutant fix, found by this round's own gate run, not left for Control plane to
   allowlist.** A first pass added `has_implausible_zero` as its own early-return branch
   (`USAGE_MISSING`, distinct detail text). The uncapped mutation gate found `if
   has_implausible_zero: -> if False` SURVIVED: disabling that branch still falls through to
   the existing `if not all_usage:` branch (which already factors `has_implausible_zero` into
   `all_usage`), producing the identical state and the identical `None`/`None` max/mean — the
   two branches were behaviourally indistinguishable by anything this suite (or any caller)

   `MALFORMED_RESPONSE`, not equivalent — confirmed KILLED at line 474 below).
