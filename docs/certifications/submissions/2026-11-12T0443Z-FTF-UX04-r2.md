## What this round does
Closes the three open round-3 findings from round 1's pre-review (route option 1 of the park entry), plus one
housekeeping fix:

1. NON-ADOPTING-HOST-RERENDER-WIPES-CREATED-FORM (sev 3). `ProjectSetupForm` reset whenever `project` was null
   and a created id was held. It now resets only on a real adopted -> null transition (a `previousProjectId` ref).
   A host that never adopts keeps the created form (name, notice, heading, focus).
2. OLDER-THAN-INITIAL-PROP-RESEEDS. The reload guard now compares against `max(seen, own)` and the form works from
   a record held at the highest version it has seen, so a racing refetch at an older version neither reverts
   fields nor makes the next save send a stale `expected_row_version`.
3. BUDGET-LATE-LOAD-PIN-IS-VACUOUS. `RequirementsPanel` has a load sequence token: only the latest GET reports.
   The new test runs two real GETs under StrictMode and resolves them out of order after a save.
4. `ftf_ux04_browser.spec.ts` takes its Chromium path from the shared `browserLaunchOptions()` helper (main #1028).

Merge of r1 onto current main conflicted in `requirements_ui.tsx` (main #34a47e26 added try/catch around the loads).
Resolved by keeping r1's `requestJson`, which already turns network failures into a typed failure shown in the
panel (same Law 17 outcome, and the main-side network-failure test still passes).
