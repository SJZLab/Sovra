## What was built

`workers/evaluation/adapters/inspect_adapter/provider_boundary.py` (pure, no I/O, no new runtime dependency) and
`tests/tasks/test_ftf_r004_p2.py` (448 checks; also run as an additive `gate` step in `.github/workflows/ci.yml`).

* `screen_outbound_model_request(body, policy)`: default-deny. Allowed tools are only `type:"function"` tools whose name is in
  the approved manifest set. Hosted tool types, `mcp`, `web_search_options` and plugin keys, remote media, unapproved function
  tools and unknown shapes are denied with stable codes (`hosted_tool_denied`, `mcp_denied`, `unapproved_bridged_tool`,
  `remote_media_dereference`, `unknown_request_shape`), every denial reported with an index path and no content.
* Hosted capabilities are allowed only under `standard` with an FTF-0901 `RouteAuthorization` that covers the `model` surface and
  an exact capability name. The profile is FTF-0901 `effective_profile`/`enforce_effect`; ordering is not re-implemented.
* `capture_response_attempts(response)` records every function call and hosted call as `AttemptEvidence` bound to the sha256
  of that exact body; `to_emitted_tool_calls()` yields FTF-0606 `EmittedToolCall` for FTF-0609 `grade_forbidden_actions`.
* `apply_approval_filter(response, evidence, approved_tool_names=...)` refuses unless `evidence` equals a fresh capture of the
  exact body, removes unapproved function calls and every hosted call, and returns the pre-filter evidence unchanged.

## Mutation gate

First run: `200 run | 155 KILLED | 45 SURVIVED`. Survivors were tests missing for case/space variants of protocol strings, evidence
validation, response-shape guards, path assertions and the depth/node limits, plus redundant code (an unused helper, a redundant
`image_url` check, string comparisons on internal constants, a `urlsplit` parse that was strictly weaker than the raw-prefix test).
The redundant code was removed and each remaining survivor got a test. One survivor exposed a real hole: `AttemptRecord` did not
validate its fields, so an always-equal `str` subclass could forge evidence that the filter's equality check accepted; it now
validates every field and a test builds the forgery. Final run:

`mutation_gate: 200 run | 200 KILLED | 0 TIMEOUT | 0 SURVIVED | 0 SURVIVED-allowlisted | score 100.0% | PASS`

## Disclosed

* UNWIRED: no live caller until FTF-R004-P3 (the runtime bridge screens each request and captures each response). Blank
  `proving_symbol`; FTF-R004 stays NONE/UNPROVEN in the spec matrix (same precedent as P1).
* BLOCKED_EXTERNAL: real upstream-route enforcement at the organization LiteLLM gateway needs the same gateway key as the
  2026-10-08 FTF-0616 owner action.
* URL classification: the packet says "classified by FTF-H006 `url_policy`". `url_policy` validates URLs that will be dialled;
  an inline `data:` payload is never dialled and has no host, so it cannot be expressed as a `ConnectionPolicy`. Inline is decided by
  the exact raw `data:` prefix (stricter than any parse); every other string is denied. Control plane may rule otherwise.
* A response with a legacy `function_call` (no call id) or an unrecognised output item raises rather than being recorded: evidence is
  never invented and never silently dropped.
