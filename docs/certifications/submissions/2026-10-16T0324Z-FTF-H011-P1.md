## E (write)

**The one additive, serialized `import_common.py` edit the IMPORTER ORDER catalog rule allows:**
`ImportMapping.row_observer: Callable[[Row, Sequence[str] | None], None] | None = field(default=None,
compare=False, repr=False)`, called first by `apply_mapping` -- before any validation -- with a
*copy* of the row and a `tuple` copy of `headers` (never the originals a mutating tap could
corrupt). Never set by `mapping_from_object`/`parse_mapping`, so no parsed MappingSpec ever
carries one, and `compare=False`/`repr=False` keep two mappings that differ only by their own
observer equal and keep a mapping's own `repr` free of an arbitrary callable. Differential proof
(Law 1): the four sibling importer suites (`test_ftf_0502.py`, `test_ftf_0503.py`,
`test_ftf_0504.py`, `test_ftf_0502_p1.py`) all pass byte-for-byte unchanged after the edit --
`candidates`/`report_sha256` for every one of their own fixtures are identical with and without
an observer attached (confirmed directly: attaching an observer and re-running every one of
those suites still reports "all checks passed").

**`workers/data/dataset_mapping_review.py`** (new, pure, no DB/network -- this task's own
`database_changes` clause "No independent schema change"): `run_mapping_probe` (headers +
raw rows only, candidates discarded, for the wizard's first step before any real mapping
exists) and `run_mapping_preview` (the real mapping over the real source: per row the locator,
masked/revealed raw row, outcome/code/slot, canonical candidate, comparison cells
`{slot, raw_type, canonical_type, identical}` and `not_mapped` columns/keys;
`observed_role_values`; `tool_definitions_sha256`; `source_schema_sha256`; `preview_sha256`;
`state`/`failure_code` for a storage outage, never a raised exception). Both dispatch by the
server-verified content type only (`jsonl`/`json`/`csv`; XLSX and anything else is
`MappingPreviewUnavailableError("importer_unavailable")` -- FTF-H011-P6 is "only after FTF-0505
is CERTIFIED", so XLSX is never silently routed anywhere else).

**`apps/api/app/datasets/dataset_mapping_service.py`** (new, read-only DB/S3): `probe_dataset_source`
and `preview_dataset_mapping`, both: load the Dataset through FTF-0501-P1 `get_dataset` (so a
foreign/missing/hidden-held-out dataset is `DatasetNotFoundError`, identical to every other
reader of this contract) -> re-authorize the connection's purpose *now*, through
`authorize_dataset_source_purpose` (Section 67.4's own "revoke/expire grant -> deny new jobs
using any descendant") -> only then `open_dataset_source` for the real bytes. Masking permission
(`reveal: bool`) is a decision this module does not make -- the eventual FTF-H011-P3 route makes
it from the connection's own `security_classification`, per this task's own "Recorded readings".

**Masking** (Section 67.2 "sensitive values are masked unless the user has preview permission",
disclosed reading, no section fixes an exact shape): a header/object key is schema, never
masked; every *value*, recursively through lists/dicts, is masked when `reveal` is False,
replaced by a type-and-size-bucket marker carrying none of the original text. One rule for
every field, never a per-slot exception -- closes this task's own fault "masking skipped or a
header left in clear" as one rule, not two.

## Disclosed, not silently decided

- `tool_definitions_sha256`: no existing module computes a canonical digest over tool
  definitions; this task introduces `compute_tool_definitions_sha256` (the same canonical-JSON
  recipe `import_common`'s own `mapping_sha256`/`report_sha256` use) as the one place that does,
  reused by both the pure module and the service layer. `None` and `{}` hash identically (both
  mean "no tool defined").
- Comparison cells for the `messages`/`messages_json` whole-array shapes compare only the whole
  array's own length against the canonical message count, not a per-message, per-field
  explosion -- a reasonable bound for an interactive preview; `prompt_completion`'s own three
  named fields (and every `metadata.*`/`group_key` slot, every shape) get a full raw/canonical
  type-and-equality cell.
- `not_mapped` cannot name a raw column addressed only by a spreadsheet `letters`-kind slot
  (XLSX is not dispatched by this module at all, so no mapping passing through here can carry
  one in practice) or a `messages_pointer` deeper than one token; both are disclosed
  approximations of a display-only field, never used to build a record.
- Held-out visibility for a preview defaults the same way `open_dataset_source` already
  requires every caller to decide explicitly (`include_held_out`, keyword-only, no default) --
  this task does not invent a new default policy for sealed data.
