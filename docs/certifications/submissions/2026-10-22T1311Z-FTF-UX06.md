## Closed (audit findings)

- **X1, sev 3 (shared component library):** rebuilt on the certified `apps/web/components/ui/`
  library — `Button` (load/load-more/edit/import/save), `Pending` (busy indicators), `EmptyState`
  (a loaded-but-empty case list). `Field`/`StatusBadge` are not used directly and `DataTable` is not
  used for the case list — see the component's own docstring and "Recorded decisions" below for why,
  disclosed rather than silently narrowed.
- **X4, sev 3 (bilingual en/ar + RTL):** every system string (labels, hints, notices, error text) now
  comes from `strings_0602.ts`'s en/ar catalogue via a new `locale` prop (defaults to `"en"`, so the
  certified `ftf_0602.spec.ts` suite is unaffected); the root `<section>` carries the matching
  `lang`/`dir`. An unshipped locale value falls back to English, not a blank render (same rule as
  `ui/phrases.ts`).
- **X3, sev 2 (error <-> field association):** every edit-form field (`category`, `severity`,
  `group_key`, `grader_type`, `weight`, the three JSON fields) is described by its own matching
  server-side field error via `aria-describedby`, in addition to the flat `edit-field-errors` list the
  certified suite already asserts on. The import textarea's `aria-describedby` points at the
  `import-field-errors` list when one exists (the import box is one control for many rows, so a
  per-row `aria-describedby` is not meaningful there — same reasoning UX_STANDARD §3.2 implies for a
  single multi-row input).
- **X7, sev 2 (busy state):** the list/import/save regions are `aria-busy` the instant a request is
  in flight (not after any delay — NN/g's own distinction between the *semantic* busy state and the
  *visible* indicator), and the shared `Pending` component (which itself waits past the NN/g 1 s
  threshold before showing anything) renders alongside. Trigger buttons are disabled for the same
  window.
- **Per-component H5, sev 2 (JSON schema hint + on-blur validation):** `input_json`, `expected_json`
  and `grader_config_json` each carry a visible, `aria-describedby`-linked hint ("Must be a JSON
  object...") and now validate on blur, before any submit — a real improvement over the pre-UX06
  submit-only check, which still runs unchanged as the authoritative gate.
- **Per-component H9, sev 2 (visual correlation for import errors):** a field error returned on a
  specific row (e.g. "Row 2 / group_key: required") now also names that row's own `case_key`, read
  back from the exact batch that was sent — not a guess, not the raw submitted value (Law 17: only an
  identifier the UI already shows elsewhere, e.g. in `case-key-{id}` spans, never a payload field).
  A request-level error (`index: null`) or an out-of-range index never fabricates a row reference.

## Recorded decisions / NOT done (do not read as closed)

- **`Field`/`StatusBadge` not adopted directly:** `Field` (ui library) only wraps `<input>`; none of
  this screen's `<select>` (severity, grader_type) or `<textarea>` (the three JSON fields) fit it, and
  no `StatusBadge` state word (draft/not_connected/.../production) describes an evaluation case. Their
  exact id/helper/error/`aria-describedby` mechanism is replicated inline rather than introducing new
  shared `Select`/`TextArea` primitives — out of this round's scope, the same kind of disclosed
  narrowing UX03 round 1 recorded for its own chip-editor deferral. Control plane to decide whether a
  later round should add those primitives to `ui/` instead.
- **`DataTable` not used for the case list:** its `<tr>` gives no per-row hook, and the certified
  `ftf_0602.spec.ts` suite asserts on one `case-row-{id}` element holding the whole row's text; the
  list keeps its `<ul>`/`<li>` structure (the suite's own `querySelectorAll("li, tr")` already
  tolerates either shape, so a future round can still move to `DataTable` without a contract break).
- **X2 (error announcement consistency):** not a finding for this component — the audit already
  records `evaluation_case_editor_import.tsx` as one of the four components that already used
  `<p role="alert">` correctly; unchanged here.
- **X6 (org/project banner) and the real-browser §72.5 viewport/keyboard/200%-zoom + automated
  accessibility-scan evidence:** deferred the same way FTF-UX03 round 1 deferred them — both need a
  rendered page (FTF-H029) or a dedicated browser harness (the kind UX01/UX03 round 2 added); not
  claimed this round.
- UNWIRED until FTF-H029 gives a live route (Law 6/7), disclosed.
- No existing certified assertion changed; every change to `ftf_0602.spec.ts`'s target file was purely
  additive and the certified suite's own 32 tests pass byte-for-byte unchanged (see Gates).
