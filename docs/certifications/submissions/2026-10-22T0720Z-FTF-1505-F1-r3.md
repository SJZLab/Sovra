## Return points -> pins

1. **HEX-GATE-SUFFIX-CAP-2MiB.** Both head-secret runs are now exactly `sr.MAX_SCAN_BYTES`
   (52,428,800) characters, so they decode to 39,321,600 bytes (base64) and 26,214,400 bytes
   (hex). No unit the scanner reads is longer.
   - The only secret now sits on byte 0 of the decoded text. Before, it sat after `token `, so
     a cap that dropped the first byte still kept it.
   - So every suffix cap shorter than the decoded unit loses the secret, down to a cap of
     decoded length minus 1.
2. **GZIP-TRUNCATION-AT-MEMBER-BOUNDARY.** Two cuts must each be a blocking `scan_incomplete`:
   - **Trailer cut.** Only the 8-byte trailer is removed (`good[:-8]`).
   - **Member-boundary cut.** The archive is rebuilt with a zlib full flush exactly at the
     secret member's header (offset 131,072), and cut there. The test checks the fixture
     itself: the cut prefix inflates to exactly the pad member, and the uncut archive has its
     secret found.

   tarfile accepts the cut prefix as a complete archive, so only the gzip integrity check can
   block it.
