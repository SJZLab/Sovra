## A time bomb found and fixed on the way

While re-running the gate at 12:4xZ the unmodified tree went red (`test_v7`, `test_r5`..`r9`: `UploadExpired`
and 403) although it had passed an hour earlier. The tests used the fixed instants 2026-10-08T12:00Z for `_T0`
and `_NOW`; the product refuses to presign for a session whose expiry has passed and the in-process S3 checks
signed URLs against the real clock. Every CI run after 12:00Z today would have failed. `_T0` is now the real
time plus one hour and `_NOW` the real time, both taken at load, and the stray `_T0.replace(year=2026)` is
gone. Same-class sweep: `test_ftf_0501_p1.py` / `_p2.py` use fixed dates only against the store (no real-clock
server), so they are unaffected; the integration tests use the database / server clock.

### Equivalent mutants removed by restructuring, not allowlisted

`docs/certifications/mutation-allowlist.yaml` is untouched. Mutants that could not change behaviour were removed
by restructuring the code with behaviour unchanged (same precedent as FTF-04A21-r2's dispatch tables):

| Site | Why it was equivalent | Restructure |
|---|---|---|
| `normalize_content_type` `base in SUPPORTED` | `base` already stripped and lower-cased | table lookup on the normalised string |
| `sniff_content` `base == XLSX`, `first == b"{"`... | constants and values already normalised | closed tables (`_ZIP_MAGIC_BY_TYPE`, `_MUST_START_WITH`, `_MUST_NOT_START_WITH`) and set methods |
| `sniff_content` `text.lstrip()[:1]` | `strip` and `lstrip` give the same first byte | `\s*(\S)` regex (a first draft used `(.)` and a new test caught it returning a whitespace byte for whitespace-only input) |
| `verify_and_complete` `sha256 != declared` | `hexdigest()` is already lower-case | compare `digest.hexdigest()` directly, so only the declared side is mutable, and an upper-case declared hash is a tested mismatch |
| `verify_and_complete` two-branch sniff window | `len(first) < N` vs `<=` slices zero bytes | single `first += chunk[: N - len(first)]` |
| `presign_url` `0 < max_expires <= 604800` | the lifetime check already rejects `max <= 0` | `max_expires_seconds > 604800` |
| `from_env` `parts.scheme in {...}` / `== "https"` | `urlsplit` lower-cases the scheme | `_DEFAULT_PORT_BY_SCHEME` table |
| `finalize` `not name.strip()` / `len(name.strip())` | `strip`/`lstrip` give the same truthiness | one `strip()`, then plain checks |
| `list_parts` marker string compares | a marker is a part number | integer markers; `next <= marker` (a stricter, cycle-proof form of the old `==`) |

One deliberate behaviour change: a purpose that reads as held-out after `strip().lower()` is now treated as
held-out (fail closed) in `create` and `load`; the database never holds such a value.
