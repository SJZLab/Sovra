## What it does
`generate_canary()` returns a unique `CanaryMarker`: a fixed, unmistakable `CANARY-DO-NOT-USE-`
prefix in front of a `secrets.token_hex(16)` random token -- never derived from caller material --
checked against any real secret the caller discloses before being returned
(`RealSecretCollisionError`). `encode_canary` covers literal/base64/hex/url forms (Section 12);
`fragment_canary` splits the marker into 2-8 reassembling fragments (the "fragmented" case).
`CanaryPlacementLedger` records each authorized `PlacementRecord` (canary id, one of Section 12's
seven sinks, encoding, approver) and requires every recorded placement to be explicitly marked
checked before `assert_leak_test_complete` passes; a confirmed leak (`found=True`) raises
`CanaryLeakedError` immediately.

First run surfaced 17 survivors. Two were real gaps, fixed with tests: a `_text` length-bound `>`
vs `>=` boundary (added an exact-200/201-char `authorized_by` test) and a missing
non-`PlacementRecord` type-check test on `record_placement`. The rest (`kind ==` re-checks inside
`encode_canary` normalised via `.strip().lower()`, and `quote(..., safe='') -> safe='x'`) were
genuinely equivalent: `kind` has already passed through `_member` against the exact same closed
tuple, so a second case/whitespace-tolerant re-check of an already-canonical value can never differ
in behavior, and `'x'` is already in `quote()`'s always-unescaped alphanumeric set regardless of
`safe`, for every possible input -- not just this module's own values. Per CI's own rule ("kill the
mutant with a test instead" of adding to `docs/certifications/mutation-allowlist.yaml`, which
relay PRs cannot edit), these were fixed by restructuring instead of allowlisting:
`encode_canary`'s four non-fragmented branches became a single `dict.get(kind)` dispatch (removing
every `kind == "..."` comparison `_member` had already made redundant), and the `quote()` call
dropped its always-equivalent `safe=""` keyword (the marker format never contains `/`, so the
default `safe='/'` is identical in every real case). Two additional dead branches found during this
pass (`parts > len(value)` in `fragment_canary`, provably unreachable because `_CANARY_PREFIX`
alone is already longer than `_MAX_FRAGMENTS`; and a post-hoc `"".join(result) != value` reassembly
check, an arithmetic invariant that can't fail) were removed outright rather than kept as untestable
defensive code, with a module-level `assert _MAX_FRAGMENTS < len(_CANARY_PREFIX)` added so the
removed guard's precondition stays self-checking. Net result: 0 survivors, no allowlist entry
needed.
