# FTF-0501-F2 -- finalize admits declared non-UTF-8 text encodings (PROVISIONAL, L1-PROVEN, not certified)

Follow-up on CERTIFIED FTF-0501 (QUEUE item, Control-plane 2026-10-20T21:15Z; found by the FTF-H011-P1 r3
verifier, #892). Law 15: FTF-0501 requalifies; the 0502-P1/0503/0504/0505/0516-P1/0519 and H011-P1 suites were re-run.
No spec-matrix edit (follow-up precedent, e.g. FTF-0512-F2): the requalification record is Control-plane's.

**Defect:** finalize sniffed UTF-8 only over the first 64 KiB, so a windows-1256 `;` CSV was refused as
text/csv, while the same file behind a >64 KiB ASCII preamble was accepted: the verdict depended on where the
first non-ASCII byte fell.

**Fix:** the upload session declares a text encoding (`declared_encoding`, one of utf-8, utf-8-sig, utf-16-le,
utf-16-be, windows-1256; default utf-8; the importers' `CSV_ENCODINGS`). Finalize decodes the WHOLE object
strictly with it (incremental, across chunk boundaries, with a final flush); the head is then sniffed on the
decoded text. One allow-list (`encodings_for`) decides what a content type may declare (a spreadsheet only the default).

**Files:** `apps/api/app/datasets/{direct_object_storage_upload,direct_object_storage_upload_routes,dataset_upload_store}.py`,
migration `0032_upload_declared_encoding` (column + CHECK only; no table, grant or policy change; the 0024 column-limited
UPDATE grant does not name it, so it is immutable after insert; RLS untouched), `packages/contracts/openapi/05-interface.yaml`
(optional request property, response property), new `tests/tasks/test_ftf_0501_f2.py` (+ additive ci.yml step), two pins updated in
`tests/tasks/test_ftf_0501.py` (frozen response keys) and `test_ftf_0501_p1.py` (model columns vs migrations 0024+0032).

**Behaviour change to note:** an object whose invalid bytes fall AFTER the 64 KiB window (or whose tail is a cut multi-byte
character) is now refused under its declared encoding; before it was accepted. That is the stated intent.
The web upload UI is unchanged (field optional, no picker); a picker is a separate UI slice with UX_STANDARD evidence.
