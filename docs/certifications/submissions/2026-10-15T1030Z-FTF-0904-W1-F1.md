## Defect and fix

`apps/api/app/log_redaction_setup.py` replaces `traceback.print_exception` with `_print_exception`, which had no
`**kwargs`. On Python 3.13 the interpreter's own fallback printer (`traceback._print_exception_bltin`, reached
when `sys.excepthook` is reset to `sys.__excepthook__`, raises, or is deleted, and by pdb post-mortem) calls
`print_exception(..., colorize=...)`. That raised `TypeError`, and the interpreter printed the traceback raw.
`_print_exception` now accepts and ignores extra keywords (`**_ignored`) and keeps the redacting writer.
A2 (callers that print `traceback.format_exc()` themselves are raw; no live path) and A3 (top-level
`SystemExit(str)`) stay disclosed, not changed.

## Tests (`tests/tasks/test_ftf_0904_w1.py`, already the `gate` step)

- W1-FALLBACK: three real subprocesses that import the app, call `create_app()`, then raise an uncaught
  `RuntimeError("password=<canary>")` with `sys.excepthook` (a) reset to `sys.__excepthook__`, (b) replaced by a hook
  that raises `ValueError("api_key=<canary>")`, (c) deleted. Each must print a `RuntimeError`/redacted traceback, never
  the canary, and no `TypeError`. Where `traceback._print_exception_bltin` does not exist (3.11/3.12) a notice is
  printed instead of a silent pass.
- W1-HOOKS gains a presence check for `sys.excepthook`, `threading.excepthook`, `sys.unraisablehook` and
  `warnings.showwarning`: with the keyword fix, 3.13's default hooks print through the replaced
  `traceback.print_exception`, so the explicit `sys.excepthook` and `threading.excepthook` replacements became
  behaviourally redundant on 3.13 (faults F7/F8 turned GREEN there). The presence check keeps them pinned on every
  interpreter, and they remain the only protection on 3.11/3.12.
