## What shipped (points 2–7)

1. **PENDING-NO-VISIBLE-PROGRESS (point 2):** `Pending`/`PendingView` now render a real
   track + fill bar (`--color-action` fill over `--color-surface-2`, width = `value`%) and a
   visible percentage, or the Arabic/English "Working…" text when indeterminate. Split the
   presentational half into `PendingView` (phase as a prop) so a test — or the browser harness —
   can render any phase without waiting on real timers.
2. **UNPINNED faults (point 3):**
   - F6 focus-visible: `tokens.css`'s own `:focus-visible` rule is now pinned (outline width
     and `var(--color-focus)`) — `[UX01-T14]`.
   - F7/F20 target size: `--target-min` (24px — the skill's own "Target Size (Minimum)" result:
     "WCAG 2.2 AA requires 24 CSS px pointer targets", not the iOS/Android 44pt/48dp figure,
     which is a different platform's rule) is now pinned, and every clickable control that was
     missing the style (`DataTable`'s sort button, `PendingView`'s Cancel button) now applies it
     — `[UX01-T15]`.
   - F17 DataTable region: a real keyboard Tab-order test (`@testing-library/user-event`) proves
     the scroll region is reachable and that Tab continues on to the sortable header —
     `[UX01-T16]`.
   - F21 Breadcrumbs: a new case gives the LAST crumb an `href` too; still renders as a `span`,
     never a link — `[UX01-T17]`.
   - F26 Pending busy label: pinned not-`aria-hidden`/not-`hidden`/not-`display:none` —
     `[UX01-T18]`.
   - F15 icon collision: a generic pairwise-distinctness test across every `StatusBadge` state
     (not just a truthy-length check) — `[UX01-T19]`.
3. **ID/ASSOCIATION (point 4):** `Button` now derives its disabled-reason id from `useId()`
   when the caller gives no `id` (previously hard-coded `"btn-reason"`, so two id-less disabled
   buttons on the same screen collided and the second announced the first's reason — reproduced
   and killed by `[UX01-T20]`). `ErrorSummary`'s title id is likewise `useId()`-derived, not the
   hard-coded `"error-summary-title"`. `Button` and `Field` now merge a caller's own
   `aria-describedby` with the component's own id instead of discarding it — `[UX01-T20]`/
   `[UX01-T20b]`.
4. **ErrorSummary refocus (point 5):** the focus effect now keys on the `errors` array identity,
   not `errors.length` — a second failed submit with the same error COUNT (a fresh array) now
   re-takes focus, where before it silently didn't — `[UX01-T21]`.
5. **Whitespace (point 6):** `Button.disabledReason` and `Field.error` are trimmed; a
   whitespace-only value is treated as absent (not disabled, no blank reason/error shown) —
   `[UX01-T22]`.
6. **Severity-2 rulings, done this round:**
   - Bilingual phrases (en/ar, RTL): `phrases.ts` gained `cancel`, `working`,
     `errorSummaryTitle`, `fieldRequired`/`fieldOptional`, `breadcrumbNav` and the ten §72.2
     status words. `ErrorSummary`, `Field`, `PendingView`, `StatusBadge` and `Breadcrumbs` take
     an optional `locale` (default `"en"`) and set `lang`/`dir` on their own root — `[UX01-T25]`.
   - `StatusBadge` never throws during render: `statusLabel()` (a pure validator a caller can
     use at submit time) still throws on a blank `blocked`/`qualified` detail; the `StatusBadge`
     component itself falls back ("Blocked — reason unavailable" / "Qualified" word alone) and
     never crashes the page — `[UX01-T23]`.
   - `Button` variants are visibly distinct, not colour-only: primary/danger fill, secondary
     outlines, and the border differs in every case (not hue alone) — `[UX01-T24]`.

## §72.5 real-browser evidence (point 7) — `apps/web/tests/ftf_ux01_browser.spec.ts`

**Scope decision, disclosed:** the harness (`apps/web/tests/browser/harness_page.tsx`) is a
**server-rendered, static** page (`react-dom/server`'s `renderToStaticMarkup`), not a hydrated
one — there is no bundler/dev-server in this repo yet (FTF-H029). This is a deliberate, narrow
scope: native `<button>`/`<a href>`/`<input>` elements keep their real tab order and focus
behaviour with zero client-side JS, which is everything the §72.5 viewport/keyboard-only/zoom
checks and the axe scan need. Interactive STATE CHANGES (a click actually firing, DataTable
actually re-sorting, Pending's real timers) are already proven for real in
`ftf_ux01.spec.ts` (jsdom + RTL + `fireEvent`/`user-event`); this harness does not re-test that.

- **Viewport (1280/768/390):** real Chromium, `document.documentElement.scrollWidth -
  clientWidth`, asserted `<= 1`px at each. Sanity-checked the methodology itself catches a real
  regression (an injected 500-char unbreakable string overflowed by 3431px at 390px width,
  confirming this isn't a tautological check).
- **200% zoom:** Chromium's `zoom` CSS property set to `2` on `documentElement`, same overflow
  check.
- **Keyboard-only:** every real interactive element (`button, a[href], input, [tabindex]`) is
  reached by repeated real `Tab` key presses; each stop's `getComputedStyle().outline*` is
  asserted non-`none`/non-zero. Negative control (`[keyboard-fault]`): the same harness with a
  `* { outline: none !important; }` reset (the actual real-world regression class — removing
  tokens.css's own rule alone isn't enough, since Chromium's UA stylesheet still outlines a bare
  `<button>`) makes the check fail, proving it isn't vacuously true.
- **Automated accessibility scan (axe-core 4.14.0, local file, no CDN):** `wcag2a`/`wcag2aa`/
  `wcag22aa` tags, 0 serious/critical violations required. **This scan found two real,
  previously-undetected target-size violations** (Breadcrumbs links and ErrorSummary links were
  below the 24px/24px-offset WCAG 2.5.8 floor) — fixed in production
  (`display:inline-block; padding-block:4px` + spacing margins), not suppressed. Negative control
  (`[axe-fault]`): a bare unlabelled `<button>` is confirmed to trip `button-name`, proving the
  scan itself finds real defects.
- **RTL:** the Arabic-locale harness sets `dir="rtl"` on the document and renders the Arabic
  status word.
