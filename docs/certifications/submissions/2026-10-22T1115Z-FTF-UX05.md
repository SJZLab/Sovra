## Recorded decisions / NOT done (do not read as closed)

- **FTF-1301 currency closed-list (H5, sev 1-2): NOT done.** The certified test
  `ftf_1301.spec.ts` "submitting the create form POSTs the real payload, then refreshes the search"
  asserts the exact typed-lowercase → sent-uppercase behaviour of the free-text `<input>`. The
  parent-slice instruction (QUEUE.md Backlog "FTF-UX02..UX07") is to keep every certified behaviour
  and API contract unchanged **except for selectors that move to role/label queries** — replacing
  free text with a closed `<select>` is a real interaction-model change, not a selector migration, so
  it is recorded as a decision rather than implemented. A non-breaking `<datalist
  id="cost-profile-currency-suggestions">` of 10 common ISO-4217 codes is wired to the existing input
  via `list=`, as guidance only: the field is still free text, and the typed-uppercase behaviour the
  certified test exercises is unchanged (new test: "UX05: the currency field offers a suggestion list
  without constraining typed input"). Control plane to decide whether this mitigation is sufficient or
  whether a proper contract change (closed enum, backend validation, migration of the certified test)
  should be routed as a separate item.
- **FTF-0214 H7 (sev 1): status/metadata filters still require a manual "Load catalog" click.** Not
  done this round (minor; the existing explicit-reload behaviour is also arguably intentional given
  the "no automatic model selection" negative-acceptance clause already on this component — changing
  it needs a Control-plane call, not a relay guess).
- **X4 (bilingual) stays open** for every pre-existing English-only sentence in these four components
  that this round did not add or touch (e.g. the `ArtifactDetails` labels in 0308, the dimension table
  in 0309, the search-results copy in 1301, the catalog/anomaly text in 0214). Same precedent as
  UX02/UX03 round 1's own "X4 stays open" note.
- **UX_STANDARD §4 full §72.5 viewport/keyboard/200% zoom/axe evidence on a real browser harness: NOT
  claimed this round.** Same precedent as UX02-r1 and UX03-r1 (both explicitly deferred this to a
  later round, since there is still no rendered page — FTF-H029 is ABSENT). This round's evidence is
  DOM-level (Vitest + React Testing Library + jsdom), consistent with every pre-UX01-certification
  round and with UX02-r1/UX03-r1's own stated scope after UX01 certified.
- Radix `Dialog` is still parked (owner has not approved it — see FTF-UX01 history); the new confirm
  in 0214 is an inline `role="alertdialog"`, the same pattern already certified in FTF-0308's own
  change-confirmation (`confirm-change`), not a focus-trapping modal.
- No existing certified assertion's *meaning* changed except the one behaviour the severity-3 finding
  requires (the probe-button click sequence in `ftf_0214.spec.ts`, four call sites updated to add the
  confirm step — see below); every other addition is a new test.
- Shared component library adoption (`Button`/`Field`/etc. from `apps/web/components/ui`): **NOT**
  done this round for these four components' existing controls (buttons/selects/inputs stay native
  elements). Rationale: every one of these controls is exercised by exact-text/exact-attribute
  certified assertions (`getByRole("button", {name: ...})`, `.disabled`, `data-testid`); `Button`'s
  own default rendering (fill colours, `min-inline/block-size`, dashed-disabled style) is a visual-only
  change and should not break text/role queries, but a full swap across four files in one round, on
  top of the probe-confirm behaviour change, was judged a larger surface than this round's budget
  should also carry without its own dedicated verification pass. Recorded as a decision for a
  follow-up round, consistent with X1 being satisfied today only by FTF-UX01's own existence, not yet
  by every consumer having adopted it (UX02/UX03/UX04 have the same open item for their own
  not-yet-migrated native controls).
