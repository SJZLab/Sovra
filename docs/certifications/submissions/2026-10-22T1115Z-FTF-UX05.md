### Finding 2 — lang/dir granularity (WCAG 3.1.2)

Root cause: the container-level `lang`/`dir` wrapped large amounts of hardcoded-English UI copy
that never actually changed under `locale="ar"` — headings, button labels, filter/select options,
status-line prefixes, `dt` labels, error-message dictionaries, confirm/notice text. Setting
`locale="ar"` therefore made assistive tech report Arabic for text that stayed English.

Fix, applied the same way across all four components, following this repo's own established
bilingual pattern (`ui/phrases.ts`'s `phrase(key, locale)`, the same mechanism FTF-UX01's certified
`apps/web/components/ui/` components and FTF-UX02/UX03's `target-application/common.ts` `fill`/
`makeT` already use for "every system string... through the en/ar catalogue"):

- **Every string these four components themselves author** — button labels, form labels, select
  option text, status-line prefixes, `dt` labels, confirm/notice sentences, the authored error
  dictionaries (previously plain `Record<string,string>` maps) — now routes through `phrase()`
  with a real `en`/`ar` pair, added to `ui/phrases.ts` (~90 new keys, one block per component).
  `phrase()` itself gained optional `vars` interpolation (the same `{name}` → value mechanism
  `target-application/common.ts`'s `fill` already established in this repo) so sentences like
  "Mapping changed: catalog version 0 -> 1. Qualification evidence recorded against version 0 no
  longer applies." can be built from translated pieces plus the real numbers.
- **Values these components do not author** — project/model/artifact names, the server's own
  closed-vocabulary enum literals (`status`, `access_state`, `metadata_status`, `capability`,
  `availability`, a dimension's `state`/`reason`), raw JSON field dumps, timestamps, actor ids, and
  a raw `detail` string surfaced verbatim for an error code with no translated entry — are data,
  not UI copy, and are wrapped in `<bdi>` (the existing `candidate_selection_ui_no_auto_selection.tsx`
  convention) rather than given a language tag whose correctness this component cannot know. One
  exception, disclosed in-line in the component: `capability_compatibility_ui.tsx`'s
  `discovery_checked_at` `dd` is **not** wrapped in `<bdi>` because a certified FTF-0309 test
  queries that `dd`'s own direct text node (`getByText(..., { selector: "dd" })`), and React
  Testing Library's default `getNodeText` only joins an element's *direct* text-node children —
  wrapping the value wrapped it instead in a nested element, making the `dd`'s own direct text
  empty and failing that exact-already-certified query. A timestamp's digits/punctuation have no
  bidi direction to isolate anyway, so leaving it as plain text costs nothing real.
- **Raw backend `detail` strings** (`readErrorDetail`'s fallback for an error code with no
  translated dictionary entry) are shown verbatim under every locale, never mistranslated — pinned
  by a new test per component ("an unrecognized backend error code/detail is data, shown verbatim,
  no claimed lang, even under locale='ar'").
- **One exception kept English-only on purpose:** `capability_compatibility_ui.tsx`'s `<section
  aria-label="Capability compatibility">` is **not** routed through `phrase()`, because the
  already-certified test "UX05: locale='ar' sets lang/dir and renders the button label in Arabic"
  queries this exact section via `screen.getByLabelText("Capability compatibility")` even under
  `locale="ar"` — translating it would break that already-certified, not-to-be-weakened assertion.
  This is disclosed with an inline code comment at the point of the decision.
- **Default `locale="en"` rendering is byte-identical to round 1**: every phrase's `en` value is
  the exact pre-existing literal text. Proof: all 107 pre-round-2 tests across the four spec files
  (`ftf_0214`/`ftf_0308`/`ftf_0309`/`ftf_1301.spec.ts`) pass **unmodified** — zero selector or
  assertion in any of them needed to change.
- New exact-Arabic-string assertions added per component, matching the rigor of other certified
  bilingual tests (e.g. `ftf_0214.spec.ts`'s existing `"UX05: locale='ar'..."` test asserting
  `"طلبًا حقيقيًا"`): new tests assert literal translated strings for buttons/labels/dt-labels/
  blockers/notices in each of the four spec files (see the fault→RED table below for a
  representative sample; the full set is in the diff).

`DimensionRow` (`capability_compatibility_ui.tsx`) now takes a separate `testIdKey` (the stable,
unchanged English identifier `data-testid="dimension-${testIdKey}"` is built from) from `label`
(the translated visible heading) — the internal selector scheme other certified tests depend on
(`getByTestId("dimension-Method support")`) is unchanged across locales, since it is this
component's own internal key, never visible copy.
