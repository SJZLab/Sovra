## Finding -> change -> test

Round 1 (#905) read a quoted secret up to its closing quote, treating a quote right after ANY
run of backslashes as escaped (`\\++[^\r\n]?` -- the whole backslash run, then unconditionally
one more character, whatever it is). That is only correct for an ODD-length run: a single
left-over backslash really does escape the next character. An EVEN-length run is backslash
*pairs*, each one a literal backslash, with nothing left over to escape anything -- the quote
right after it is the real terminator, not more content.

`password="V\\"` (two backslashes) is the textbook even case the Control-plane verifier found:
- On the `_KEY_VALUE`/`_HEADER` path (`_QUOTED_VALUE`, secret-named keys: password, token,
  secret, api_key, ...): the quoted-value alternative failed to match at all (its content loop
  consumed the real closing quote as "escaped", then found no second quote before end of line),
  and the plain fallback `[^\s&,;"'}\])]+` excludes quotes outright -- so nothing matched and the
  whole line leaked verbatim.
- On the query-param path (`_QUOTED_SECRET`, the `_F2_NAMES` last-word class: state, code,
  session, sig, ..., with an optional trailing quote for the unterminated-quote-runs-to-EOL
  rule): the same mis-consumption let the content loop run past the real close into whatever
  followed on the line, over-redacting legitimate trailing text (`{"password": "V\\"}` and
  `session_key="V\\" after` both lost their trailing `}` / ` after`).

**Change** (`packages/security/log_redaction.py`): both `_QUOTED_VALUE`'s and `_QUOTED_SECRET`'s
backslash-run content branch now pairs backslashes two at a time, possessively --
`(?:\\\\)++(?:\\[^\r\n])?` in place of `\\++[^\r\n]?` -- so only a genuinely left-over single
backslash (odd run) pairs with the next character as an escape; an even run never reaches that
optional escape, leaving the real closing quote for the literal `"`/`'` alternative. Also
restructured `_QUOTED_SECRET`'s own raw-string literal boundaries (single-quote delimiter for the
double-quote branch) so this and future single-character mutations of its tail stay valid Python
-- the previous layout had the branch's content ending in the SAME character (`"`) as its own
`"""` delimiter, which a naive "drop the trailing `?`" mutation turns into 4 consecutive quote
characters and a `SyntaxError` instead of a behavioural change.

**Test** (`tests/tasks/test_ftf_0904.py`): two new generated-table tests sweep both credential-name
classes (`_SECRET_KEY_WORDS`: password/token/api_key/client_secret/secret, and `_F2_NAMES`), both
quote styles, both separator forms, across backslash-run lengths 0-6 before the closing quote:
- `test_f2_r2_even_backslash_run_closes_the_value_cleanly` (even runs 0/2/4/6): the marker must be
  redacted (`[REDACTED]` present, not leaked) and trailing text after the real close must survive
  (`out.endswith(" tail_ok")` -- catches over-redaction, not just leaks).
- `test_f2_r2_odd_backslash_run_still_escapes_the_quote` (odd runs 1/3/5): the first quote after
  the run is escaped by design, so a second, later quote is the real close; the marker AND the
  intervening plain text ("more") must not leak, and trailing text must survive.
