> inspects only `str(exc)+repr(exc.args)`. Also require, for every refusal, `exc.__cause__ is
> None`, `exc.__context__ is None`, `not getattr(exc, "__notes__", None)` and `vars(exc) == {}`
> (production meets all four today), or scan the whole `traceback.format_exception(exc)` output
> plus notes for the marker.
>
> Faults that must go RED behaviourally: C3 - `_number_value` does `float(value)` on a str and
> raises the refusal inside `except ValueError`, so `__context__` carries the caller text into
> `logger.exception` output (fully GREEN today); C1 - `_id_value` raises `... from
> ValueError(value)` for ContentRef ids; C4 - `err.add_note(str(value))`; C5 - the value stored as
> an exception attribute (C1, C4, C5 RED today only through the meta checks).
>
> Still passing on two consecutive runs in one checkout.

Scope: **tests only**, `tests/tasks/test_ftf_0903.py`. No production change — production (
`packages/security/content_free_telemetry.py`) already satisfies all four meta conditions on
every refusal path; the gap was entirely in the test file's own echo detectors not looking past
`str(exc)`/`repr(exc.args)`.

## What changed

1. **`_meta_clean(exc)`** (new shared helper): `exc.__cause__ is None and exc.__context__ is None
   and not getattr(exc, "__notes__", None) and vars(exc) == {}`.
2. **Every echo helper named in the ask now requires it, in addition to its existing marker
   check** — "fix the whole class, not one more case":
   - `_message_of`: appends `|META-LEAK` to its returned string when `_meta_clean` fails (existing
     substring assertions in rounds 2-4 are unaffected: production is clean, so this never fires
     on unmutated code).
   - `_echo_report`: returns `"LEAK"` when the marker is absent from `str(exc)+repr(exc.args)`
     *and* `_meta_clean` fails (previously returned `"clean"` in that case).
   - `_r4_echo_report`: same change.
   - `_PROBE_R3`'s inline subprocess `outcome(fn)` and `_PROBE_R4`'s inline subprocess
     `report(fn, *markers)`: each gained an inline `meta_clean(exc)` (subprocess has no access to
     the test module's own helper) and now returns `"LEAK"` when it fails, even if the marker
     itself never reached `str(exc)`/`repr(exc.args)`.
3. **New round-6 section** (`_PROBE_R6`, `BASELINE_R6`, `_r6_mutations()`, two new tests):
   - `test_round6_message_of_and_echo_reports_require_clean_exception_metadata` — a **negative**
     test: runs today's real, unmutated production with the attack marker present on three
     different helpers and asserts the clean outcome (no `META-LEAK`, `"clean"`), proving the new
     checks do not false-positive on correct code.
   - `test_round6_meta_leak_faults_each_turn_the_probe_red` — the Law-1 fault-injection proof: a
     dedicated subprocess probe with 4 cases (one per C1/C3/C4/C5 target), baseline all `"clean"`,
     then each of the four mutations below applied one at a time and shown to turn **exactly its
     own index** `"LEAK"` while the other three stay `"clean"`.
