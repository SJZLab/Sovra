`_artifact()` now takes optional `license_id`/`license_accepted_by`/`license_accepted_at`

  `LineageFact` one at a time, each on an otherwise-untouched fact.

Plus 7 fault-injection tests (Law 1), each mutating the real on-disk module, running a fresh

- `test_fault_injection_r4_license_detail_drops_accepted_by_is_caught`

- `test_fault_injection_r4_canonical_fact_drops_detail_key_is_caught`

- `test_fault_injection_r4_canonical_fact_drops_known_key_is_caught`

**Bytecode-cache correctness fix (found while developing this round):** running the three
`_canonical_fact`-drop fault tests back to back was flaky — the third (`drops_value_key`) failed
intermittently even though the module was correctly restored byte-identical after each test.
Root cause: CPython's default `.pyc` cache invalidation is timestamp+size based, not
content-based; three rapid rewrites of the same file within one mtime tick let a subprocess
`import` silently serve a STALE cached bytecode from an earlier test's mutation instead of the
current on-disk source. Fixed by deleting the module's cached `.pyc` after every write inside the
new `_run_r4_fault`/`_run_r4_value_fault` helpers (`_invalidate_pycache`), and running the probe
subprocess with `PYTHONDONTWRITEBYTECODE=1`. Confirmed stable across 5 consecutive full-suite runs
after the fix (0 flakes); reproduced the flake deterministically beforehand to confirm the
diagnosis before writing the fix.
