## Production change (`scripts/task_claim.py`)
- New `ADDENDA_DIR = REPO_ROOT / "spec" / "addenda"`.
- New `is_addendum_task(task_id, addenda_dir=ADDENDA_DIR) -> bool`: true iff `spec/addenda/<id>.json` exists.
- New `certified_ids_missing_from_tasks_json(certified_ids, tasks_by_id, addenda_dir=ADDENDA_DIR) -> set[str]`:
  the real ids `spec/tasks.json` fails to reflect as CERTIFIED, excluding only genuine addendum ids. A
  non-addendum id missing from `tasks_by_id` is never excused.
- `sync_certified_status`: new `addenda_dir` parameter. `spec/tasks.json` and `docs/implementation/TRACKER.json`
  now track separate `tasks_updated`/`tracker_updated` lists and each file is written only when its own list is
  non-empty (previously the tracker write was gated on `tasks_updated`, so a tracker-only change was silently
  dropped). When a CERTIFIED id has no `TRACKER.json` entry and is a real addendum, a new entry is created
  (`status`, empty `commits`, `evidence` from the spec-matrix's `evidence_hash`, `independent_review: None`,
  `blockers: []`) — the same shape every other `TRACKER.json` entry already uses. A non-addendum id with no
  tracker entry is left alone (unrelated, pre-existing gap; out of this task's `files` scope). Return value is
  unchanged in shape: the sorted union of ids updated in either file.
