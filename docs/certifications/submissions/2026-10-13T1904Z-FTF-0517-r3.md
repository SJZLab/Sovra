## Fix (production, workers/data/group_aware_split_engine.py)
- `_text`: `isinstance(value, str)` -> `type(value) is not str`. Closes the concrete hole: a str
  subclass with foreign `__hash__`/`__eq__` and the same text as a plain-str key hashes
  differently in the union-find dict, so it silently fails to merge with an identical-looking
  plain-str key and splits one family across two groups (and therefore two roles) instead of
  raising. Applies to every caller of `_text`: group keys, `record_id`, `SplitSpec.seed`.
- `preassigned_role` check: type-checked (`type(...) is not str`) *before* the `in _IS_EVAL`
  membership test, so an unhashable value (`[]`/`{}`) raises `SplitEngineError`, not a raw
  `TypeError` from hashing it for the dict lookup.
- `verify_manifest`'s assignment loop: each entry is now checked for exact 3-tuple structure and
  `type(record_id)`/`type(group_id)` is `str` *before* any dict lookup or unpacking is trusted,
  and `type(role) is not str` is checked before the `role not in _IS_EVAL` membership test — same
  "type before membership" shape as the `preassigned_role` fix, so a malformed or unhashable
  entry raises this module's own error instead of a raw `TypeError`/`ValueError`.

No union/merge logic changed — the verifier's own finding is that `group_keys[1:]` (every key
past the first) was already correct; the gap was in the test suite's own coverage of 3+-key
records, not production.
