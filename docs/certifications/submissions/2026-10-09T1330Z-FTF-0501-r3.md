## Real SeaweedFS paging (found in CI, fixed)
The first real-server runs (job `direct-upload-routes-integration`) showed SeaweedFS 3.99 lists multipart uploads in **upload-id** order, flags a full page truncated with only `NextUploadIdMarker` (no `NextKeyMarker`), answers a page request carrying both markers with an empty page, and pages correctly with `upload-id-marker` alone (7 remaining returned). `list_multipart_uploads_page` therefore: uses the S3 pair when both markers come back, carries the upload id alone when only `NextUploadIdMarker` comes back (sends only `upload-id-marker`), and falls back to the last entry returned when neither does; an empty truncated page is refused. Tests: S8 (all marker shapes), S10 (FakeS3 in SeaweedFS paging mode: 1005 uploads, stale one behind 1004 others, aborted, others kept), and W3 on the real server.
