## Point 1 — MUTATION-KILL-BY-TEXT-GUARD

**Problem:** the mutation gate (`scripts/mutation_gate.py`) mutates the production module on disk
and runs this test file to decide KILLED/SURVIVED. `main()`'s H1 loop re-patches the *already
mutated* source text against its own hardcoded `FAULTS` strings; when the gate's own AST mutation
happens to touch text a `FAULTS` entry also targets, the patch's exact-count match
(`source.count(old) != count`) can fail against the mutated text for a reason that has nothing to
do with whether the behavioural suite caught the gate's mutation — counting the mutant "killed" by
an accident of the harness, not by real coverage (round 3's point 1: "the kill signal... must
ignore `[H1]`").

**Fix:** added the same `BEHAVIOUR_ONLY` detection FTF-0904 and FTF-0616-F1 already use and the
owner already approved live (2026-10-21, PR #930's own description: "the mode the mutation gate
already uses"):
```python
UNDER_MUTATION_GATE = "mutation-gate-pyc" in os.environ.get("PYTHONPYCACHEPREFIX", "")
BEHAVIOUR_ONLY = os.environ.get("FTF_H010_P3A_BEHAVIOUR_ONLY") == "1" or UNDER_MUTATION_GATE
```
`scripts/mutation_gate.py` already sets `PYTHONPYCACHEPREFIX` to a `mutation-gate-pyc-*` tempdir for
every suite it runs (no suite-specific config exists or is needed — confirmed by grep: no
`test_ftf_h010_p3a` reference anywhere in `scripts/mutation_gate.py`, `.github/workflows/ci.yml`'s
own mutation-gate step, or `docs/certifications/mutation-allowlist.yaml`). `main()`'s H1 loop is now
skipped when `BEHAVIOUR_ONLY`, so the gate's kill signal is the behavioural suite alone, exactly
like every other suite.
