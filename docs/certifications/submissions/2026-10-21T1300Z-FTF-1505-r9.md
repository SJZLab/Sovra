## The ruling's pin

`test_unit_sized_base64_and_hex_runs_are_scanned_end_to_end` builds the runs from the module's own
`MAX_SCAN_BYTES`:

- **Length.** One base64 run and one hex run, each exactly `sr.MAX_SCAN_BYTES` (52,428,800)
  characters. No unit the scanner reads can be longer, so a bound of that size or more is a no-op.
- **Placement.** Each run is tiled end to end with distinct `github_token` seeds, one space apart:
  873,813 seeds in base64 and 582,542 in hex. The last seed ends on the run's last byte.
- **Path.** Both runs go through `scan_line` itself, the function every lane calls, and every seed
  must come back.

Any bound shorter than a unit loses the tail. A cap that splits the run into chunks that still
decode cuts through the seed lying at a chunk boundary. The test takes about 75 s.

  - **Base64 regex caps:** `{24,1066667}` (B10), `{24,1000000}`, `{24,4000000}`, `{24,16000000}`,
    `{24,52428796}`.
