## New-test placement and why each is a real gap, not equivalent
- **C6**: the pre-existing conflict test only exercised the "Keep mine" / "Take server's" buttons;
  nothing drove `handleEdit` while a draft was already in `conflict` state, so the mutation that
  resets `baseText` on every edit (silently promoting a stale conflict to a normal unsaved edit)
  had no test watching it.
- **P7**: `draftStorageKey`'s own uniqueness and the cross-manifest isolation it exists to provide
  were never asserted directly — every prior test used a single, fixed `MANIFEST_ID`.
- **S8**: the existing null-save test ("clearing the agent name saves null") only covers the
  `TEXT_FIELDS` path (`agent_name`), which is a different branch in `handleSaveDraft` from the
  JSON-field branch that the fault targets.
- **D3**: the existing `lineDiff` test only covers same-length before/after strings (a replaced
  middle line); no test drove the two asymmetric-length tail loops, so a mutation to either one
  (this round targeted the trailing-`added` loop) went unnoticed.
