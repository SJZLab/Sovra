## The 32 original survivors, by cause

**28 real gaps, closed with new tests (no production change needed — every one was a missing test,
not a missing guard):**

- **`_stored_reviews` (14 survivors, lines 261-285):** `patched()` replaces this function outright
  for every HTTP-level check in `route_suite`, so its real body — the SQLAlchemy `select().where()`
  predicate and the stored-shape validation — never ran behind any existing test. Added
  `test_u_private_helpers_behave`, which fakes only `execute_tenant_scoped` (so the real function
  body executes) and evaluates the actual compiled WHERE-clause operators/values against a small
  row table. This kills the `==`→`!=` column-predicate mutants (a crafted two-row table where only
  the correct predicate selects the intended row), the `insert return None first` mutant (a
  happy-path parse that must return real pairs), and every stored-shape mutant (non-list, non-dict
  item, non-string `finding_id`/`rationale`) — each checked against a value that still parses fine
  if the specific guard is skipped, not one that fails for an unrelated reason (the first attempt at
  the non-list case used a plain string, which still produces `None` under the mutation because
  Python iterates a string into single-char "non-dict" items and the next guard still fires —
  caught by a dedicated local mutation re-run after the first full CI-equivalent pass, fixed with a
  tuple-of-one-valid-dict so the type guard is the only thing standing between it and a real parse).
  The four `.strip().lower()` mutants on `DatasetSplitManifest.id`/`.project_id` and the
  `manifest_id`/`project_id` parameters need no test at all: `.strip()` is not a method either a
  SQLAlchemy `InstrumentedAttribute` or a `uuid.UUID` has, so that mutation raises `AttributeError`
  while the statement is being built, before any fake is reached — confirmed directly in a Python
  shell against the real module.
- **`_scalar` (3 survivors, lines 126/128/132):** direct unit checks in the same new test function:
  a `None` value on a UUID-typed field name must short-circuit to `None` rather than fall through to
  `str(None)`; a messy field name (`" ID "`) must never be folded by `.strip().lower()` into a UUID
  field; a tuple value must come back a real `list`, not pass through unchanged.
- **`_parse_reviews` boundary (1 survivor, line 231):** the existing suite tested 401-char
  `finding_id` (rejected) but never exactly 400 (the inclusive upper bound) — added an acceptance
  check.
- **`list_manifests`/`approve`/`reject` each losing a `TenantContextError` (3 survivors, lines
  347/462/527):** no existing test ever triggered this exception on any of the three routes — added
  one `fake.raise_other = TenantContextError(...)` check per route, each asserting 404, not a 500.
- **`_replayed`'s `stored is None` guard (1 survivor, line 391):** forced `_stored_reviews` to return
  `None` via a new `FakeStore.stored_reviews_override` on an already-locked, otherwise-matching
  manifest; unguarded, `_fingerprint` is called with `reviews=None` and `sorted(None)` raises
  `TypeError`, turning a would-be 409 into an unhandled 500.
- **`_replayed`'s reject-branch status check (1 survivor, line 395):** a manifest with
  `status=" REJECTED "` (case/whitespace messy — a defensive check against a store/DB-layer bug, not
  a value any current caller produces) must not be folded into "already rejected" and handed a
  replay.
- **approve/reject's own `exc.code != "manifest_not_proposed"` race-shortcut guard (7 survivors:
  the `if False` and `!=`→`==` variants on both routes' own guard line, plus `raise`→`pass` on both
  routes' own re-raise line):** the existing "concurrent duplicate request" test only used
  `raise_code="manifest_not_proposed"` (the one case where the shortcut *should* fire). Added a
  symmetric race test per route with `raise_code="manifest_tampered"` — a distinct, real `CODES`
  member — where the concurrent write also side-effects the manifest into an already-matching
  locked/rejected state; the guard must still re-raise `manifest_tampered` rather than slip into the
  replay shortcut just because the state happens to match. Added a clean-canonical race test for
  reject (`"manifest_not_proposed"` exactly, mirroring the approve-side one that already existed) to
  separately pin the `!=`→`==` operator-flip mutant, which the tampered-code test alone doesn't
  reach (that mutant only changes behaviour for inputs where the *correct* code is exactly
  `"manifest_not_proposed"`).

**4 genuine equivalent mutants, not tested (disclosed, not allowlisted — relay cannot write
`docs/certifications/mutation-allowlist.yaml`; that is a Control-plane action per the CI job's own
`relay-policy` rule):**

- `_refusal`, `approve`, `reject` each comparing `exc.code` normalized by `.strip().lower()`
  (lines 304/446/512) — `SplitManifestError.__init__` asserts `code in CODES`, and every one of the
  22 `CODES` members is already lowercase with no whitespace, so **no `SplitManifestError` can be
  constructed with a code `.strip().lower()` would change at all** — confirmed directly: attempting
  `SplitManifestError(" Actor_Not_Permitted ")` in a Python shell against the real module raises
  `AssertionError` from the constructor itself, before `_refusal` or any route ever sees it.
- `_replayed`'s `action` parameter normalized the same way (line 387) — `action` is always the
  literal `"approve"` or `"reject"` at its only two call sites (both inside the same module, neither
  derived from any request input), so no caller can ever supply a messy value either.

These four are the same class this repository has already certified under elsewhere (e.g.
FTF-0505's "S05" equivalent, FTF-0512-F1's reviewed equivalents) — a provably-unreachable
differentiating input, not a missing test.
