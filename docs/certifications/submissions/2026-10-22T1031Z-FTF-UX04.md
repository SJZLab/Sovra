## Audit findings fixed (docs/design/audit-2026-10.md)

- §10 H8 (sev 1): "Create/Save changes" is now `variant="primary"` and "Save draft" `secondary` (UX01 Button).
- §11 H5 (sev 2): the budget total is checked **before submit** against the already-reserved amount, in exact decimal
  arithmetic (`toUnits`, BigInt; never floats), and the message names the minimum ("Enter 400.0000 or more.").

Defects found by reading the code against the backend, fixed here (each has a test and a real-API scenario):
1. A network failure (rejected `fetch`) was an unhandled rejection with nothing shown (H1/H9). Now a typed `Failure`.
2. A 2xx with a malformed or unrelated body was reported as saved (Law 17 / CHECKLIST a, b, d). Now refused.
3. The component kept sending the stale `project.row_version` prop after its own successful save, so a second save
   409'd. The saved record now supplies the next version; an externally newer record re-seeds the form.
4. After a create the form stayed in create mode, so a second click created a duplicate project. It now becomes that project.
5. Clearing a description sent `null`, which the API skips, so it silently did nothing. Sent as `""`; stored as `""` (R3).
6. `security_profile` was free text; the backend accepts a closed set and refuses a relaxation (400). Now a `select` of
   the closed set; a server-held value outside it stays visible and selected, never swapped.
7. A saved draft (`ui_state`) was written but never read back (docstring promised resume). Now offered, never applied silently.
8. The budget `currency` was free text capped at 3 chars; the backend recognizes 10 codes. Now a `select` of them.
9. "Draft saved" and "Changes saved" had no relation to what the server returned; both now require a bound reply.

## Decisions for the Control plane (Law 9 record)

- **D1 parent assertions tightened, intent unchanged** (`ftf_0401.spec.ts`, `ftf_0408.spec.ts`; 6 assertions): the create/draft
  mock replies now echo the request (CHECKLIST b/d: a reply that is not this request's result is no longer a save), the create
  budget fixture is version 1, and three error assertions now expect the localized sentence instead of the raw backend `detail`
  (the UX03 precedent: `detail` is an internal code or an English developer sentence). A *tightening*: each parent still pins the
  same behaviour and now also pins that the code does not leak. 17/17 parent tests green.
- **D2 sentences, not `detail`**: `mandateFailureMessage` maps status → sentence + next step in en/ar.
- **D3 a budget GET 404 stays "no policy yet"**: the route answers `not_found` for a missing policy AND for a project it cannot
  show; the create state is shown, and creating then answers 404 which is shown as "project not found" (R13).
- **D4 (sev 2) no discard-confirmation and no navigation guard**: the Radix Dialog dependency is still an open Owner action
  (QUEUE.md "Owner actions — current", 2026-10-20), and a navigation guard belongs to the app shell (FTF-H029). The component
  offers Cancel (caller-owned), keeps entries on every failure, and has Save draft + restore as the recovery path.
- **D5 `DataTable` instead of a hand-built table**: consistency (H4) and sortable columns; the tool name moved from a row header
  (`th scope=row`) into the first cell, with `requirement-row-<id>` on the cell's span.
- **D6 `onCancel` is optional** and sends nothing.
- **D7 Latin digits for amounts** in both locales: they are exact decimal strings bound to what the API stores and returns;
  localizing digits would show a value that is not the one sent.
- **D8 (corrected in review round 1)** the late-reply guard is kept on the FORM: a save that finishes after the form switched to
  another project must not reach `onSaved` (restored and pinned). On the PANEL the guard stays removed: it has no caller callback, a late reply
  lands on an unmounted instance, and nothing observable depends on it (reviewer probe P15 passes).
