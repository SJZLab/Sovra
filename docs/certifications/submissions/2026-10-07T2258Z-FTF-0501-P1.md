## Defects found and fixed in the inherited draft (the new tests exposed them)
1. **Finalize never worked.** `record_upload_verified_and_create_dataset` flushed the session UPDATE and the dataset
   INSERT together; SQLAlchemy INSERTs first, so the composite FK to the `verified` session failed, and the blanket
   `IntegrityError` -> `DatasetVersionConflictError` relabelled it. Fixed with an explicit flush of the session first;
   the conflict mapping now fires only for `uq_datasets_project_name_version`, anything else re-raises.
2. **Verified sessions were rewritable.** `finalized_at` (and `updated_at`) of a verified, dataset-referenced session
   could still be changed by `sovra_app`. Added `tr_dataset_upload_sessions_freeze_verified` (BEFORE UPDATE, refuses any
   change once `status='verified'`), dropped in downgrade.
3. **Alembic head collision.** The draft's `0023_dataset_uploads` collided with merged `0023_evaluation_cases`; renumbered
   to `0024_dataset_uploads` chained on it (single head asserted in both test files).
