## Findings -> change -> test
1. **Denial broke the caller's tenant-scoped session (DB3/DB3b).** The denial's `session.commit()` ends the transaction that held `set_config(..., is_local=true)`. Fix (QUEUE's second route, "re-bind after the commit"): the tenant is read from the caller's session up front (`current_setting('app.current_organization_id', true)`) and bound again right after the commit. Real Postgres, `sovra_app`, real `tenant_scoped_session`: two denials in one session give 2 typed `ExternalProviderDeniedError`, 2 durable rows, and the caller's own count read after each denial is 6 then 7 (was 0).
2. **Uncommitted caller work was committed (DB4).** Fix: a session with new/dirty/deleted ORM state, or any write already flushed in the open transaction (`txid_current_if_assigned() IS NOT NULL`), is refused with `external_provider_invalid_request` before any decision, on the allow path too. Real Postgres: both an unflushed and a flushed caller row are never persisted, the request is refused, and no audit row is written for the refused request.
3. Docstring and spec-matrix note updated (the audit is still on the caller's session; the precondition is now enforced, not only documented).
