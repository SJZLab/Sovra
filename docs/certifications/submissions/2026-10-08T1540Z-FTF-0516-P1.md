## Decisions where the QUEUE entry was silent (default-resolution rule)
- `has_positions` is a plain column held true by a CHECK, not a GENERATED column: the database refuses a wrong flag from any writer either way, and a plain column stays a portable ORM attribute for the no-DB tests.
- `correct`/`new_version` with a successor of another name or purpose is `400 invalid_body` (the contract's code list has no dedicated code); a hidden/missing successor is `404 not_found`.
- Replay returns 200, a fresh write 201. `GET issue-resolutions` returns the most recent decisions across reports, newest first, limit only.
- Audit `resource_id` is the resolution id (issue ids are content hashes and repeat across reports); the issue id is in `details`.
- Reports are chained (`report_sha256` covers the previous report's hash) so a later report never collides with an older one holding the same findings under `UQ(dataset_id, report_sha256)`.
- The API now imports `workers.data.quality_issue_engine`, so the repo root must be on `sys.path` at runtime (the compose file sets `PYTHONPATH=/app/apps/api`; cwd is the repo root).
