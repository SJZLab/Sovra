## What changed (Control-plane ruling)

exact `dict`/`list`/`str`/`int`/`float`/`bool`/`None`, exact-`str` keys, checked recursively (`_plain_copy`). They build
their own `TrainingTrace` (`_trace_from_plain`) and `ReviewDecision` (`_review_from_plain`) from the copy.
- Any caller `TrainingTrace` or `ReviewDecision` (exact type, subclass, or one whose `__dict__` key rewrites values on every read:
  P8b, P8f, P11b) is refused before anything is read from it.
- `index` comes from one `_check_provenance` call and is used for the regenerated trace and the duplicate-index guard;
  `trace_id`, `reviewer_id` and `decision` are read once into locals; `by_id` is keyed by the regenerated trace_id.
- API change: callers pass `TrainingTrace.to_dict()` output and `{"trace_id","reviewer_id","decision"}` dicts.
  There is no other production caller of these functions (grep: only the test file).
