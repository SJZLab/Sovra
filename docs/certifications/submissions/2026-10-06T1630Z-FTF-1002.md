## Fix — `apps/api/app/artifacts/artifact_lineage_manifest.py`

(a) **Format validation.** `model_version.weights_digest`/`artifact.weights_digest` and
`model_version.base_model_revision`/`artifact.base_model_revision` are now re-validated with the
shared `validate_weights_digest`/`validate_base_model_revision` (from `artifact_schema.py`) right
after the id-match check, raising `ArtifactLineageError` on any malformed/blank value — never trusting
that `TrainableArtifact.__init__`'s own validation already ran (an ORM-loaded row skips it).

(b) **Adapter base identity.**
- `resolved_base_artifact.weights_digest`/`base_model_revision` are now re-validated the same way,
  raising `AdapterBaseMismatchError` on malformed input.
- A new `model_family` identity check: `resolved_base_artifact.model_family != artifact.model_family`
  is refused — a resolved base of a different family can no longer pass on a coincidentally-matching
  `base_model_revision` string alone.
- The self-digest comparison (`resolved_base_artifact.weights_digest == artifact.weights_digest`)
  stays a plain `==`, not case-insensitive — correctly so, since by the time either digest reaches
  this line, (a)'s format validation has already required both to be canonical lowercase hex. A
  case-variant digest is refused earlier, by (a), not by this comparison; the fault-injection test
  for this item (below) targets the real guard, not a redundant one.
- The resolved base's own `id`, `weights_digest`, `model_family` and `source_uri` are now recorded in
  the `base` `LineageFact`'s `detail` string for an adapter import — previously only the adapter's own
  declared `base_model_revision` was recorded.

(c) **Endpoint + resolved_base_artifact.** An `endpoint` import with a `resolved_base_artifact`
supplied is now refused (`ArtifactLineageError`) rather than silently ignored — `resolved_base_artifact`
is only ever meaningful for an `adapter` import, and an endpoint has no local artifact at all.

(d) **Test fixtures** (`tests/tasks/test_ftf_1002.py`): the tamper-detection test now mutates EVERY
field the manifest's own digest claims to cover (`model_version_id`, `import_kind`, and each of the
seven `LineageFact` dimensions), one at a time on a fresh manifest, instead of only `import_kind` — a
field `_compute_manifest_digest` silently omitted would previously have gone undetected forever. A new
test confirms two manifests sharing the same `model_version_id` but built from artifacts with distinct
`weights_digest` values produce distinct `manifest_digest` values (rules out a digest computed mostly
or only from `model_version_id`).
