# FTF-0502-P1-F1 round 1 — resumable dataset source reads

PROVISIONAL / L1-PROVEN, not self-certified (Law 4). Follow-up on CERTIFIED FTF-0502-P1; Law 15: P1 is requalified with it.

## Change
- `S3Client.stream_object_windows` (storage_semantics_client.py): reads the object in bounded Range windows (8 MiB). The first window fixes ETag and total size; later windows send `If-Match`, and each answer must carry the same ETag and size. A 412, a different ETag or a different size raises `S3ObjectChanged` (never spliced bytes). Anything that is not a 206 with a matching `Content-Range`, a missing ETag, a short window or a bare 416 raises (outage), and an empty object (416 `bytes */0`) yields nothing.
- `dataset_object_source._stream` uses it, maps `S3ObjectChanged` to `DatasetSourceChangedError` (`source_changed = True`), everything else stays `UploadStorageUnavailableError` (Law 17).
- `ChunkReader` (import_common.py): a source exception whose `source_changed` is exactly `True` ends `failed` / `source_changed`; every other exception stays `blocked` / `source_unavailable`. The whole-stream sha256 check at the end is unchanged.

## Disclosed limitation
This sandbox has no Docker daemon, so the real-SeaweedFS checks could not run here. The integration suite (tests/integration/test_ftf_0502_p1_dataset_source_postgres_s3.py) gained I6 (96 MiB dataset consumed at 1 MiB/s completes with the right sha), I7 (object overwritten between windows ends failed/source_changed) and an updated I4 (one windowed read, no listing); the existing I5 stop-mid-stream check stays. `dataset-import-source-integration` in CI is the authoritative run. Whether SeaweedFS honors `If-Match` on ranged GET is not assumed: the ETag/size comparison on every window covers a server that ignores it. Local unit evidence uses a scripted Range/If-Match HTTP server through the real signed S3Client.
