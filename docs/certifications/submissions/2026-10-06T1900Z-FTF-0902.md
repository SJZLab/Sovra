## Defect
`render_network_policy_manifest` emitted the module-level `KUBE_DNS_NAMESPACE_LABELS` / `KUBE_DNS_POD_LABELS` dicts by
reference. Clearing them in one returned manifest made every later render emit empty selectors (all pods, all
namespaces) on port 53.

## Fix
- The two constants are now read-only `MappingProxyType` mappings (cannot be cleared in place).
- New `_kube_dns_selector_labels()` returns fresh `dict` copies per render and raises `MissingExplicitScopingError`
  if either is empty (fail closed, never emits an empty selector).
- `render_network_policy_manifest` builds the DNS rule only from those copies.

## Test (`test_dns_rule_is_never_shared_between_renders`, run as `python3 tests/tasks/test_ftf_0902.py`)
Literal expected selectors (not the production constants); mutates/clears a returned manifest then re-renders; asserts
no returned selector is the module constant and two renders share no dict; asserts the constants cannot be cleared in
place; rebinds each constant to `{}` and asserts render refuses and never emits an empty selector (negative test on the
real default code with the attack input present).
