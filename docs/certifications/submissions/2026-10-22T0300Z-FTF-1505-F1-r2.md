## Return points -> pins

`test_f1_r2_head_only_secret_in_a_long_run_and_salvaged_tgz`:

1. **QUICK-GATE-SUFFIX-CAP.** Every earlier long-run test also had a secret near the end of the
   run, so a pre-filter that read only the end of the decoded text passed them. The new test
   uses one base64 run (3,000,000 raw bytes) and one hex run (2,000,000 raw bytes), each over
   2 MiB. Each holds its only `github_token` on its first bytes and goes through `scan_line`.
2. **GZIP-SALVAGE.** The F1 archive was smaller than one 64 KiB read, so keeping the part of a
   corrupted stream read before the error passed. The new archive has a pad member that ends
   exactly on a 128 KiB boundary, followed by a member holding a secret.
   - Intact, the secret must be found.
   - With a corrupted CRC trailer, or truncated by 50 bytes, it must be a blocking `scan_incomplete`.
