## What changed
Production: `apps/web/components/dataset-factory/resumable_dataset_upload_ui.tsx` (rewritten around strict parsing and binding).
1. **Return 1 (finalize).** "Dataset created." appears only for a **201** whose Dataset passes `parseUploadedDataset`: every field typed, and bound to the organization prop, the session's project, the trimmed name sent, the session's purpose, id, declared SHA-256 and size. A 200 / 202 / 204, an unbound body, a non-JSON body or a thrown fetch is a "malformed / unknown outcome" state that keeps the draft and offers a read-only "Check upload status" (a verified session then shows a terminal "already finalized" state). UF8 closed.
2. **Return 2 (bind every field sent).** One binding function per reply: `sessionMatches` (create reply to purpose / size / sha / content type / connection / project and status `open`; a resumed session to the draft incl. id), `parsePartsListing` (plan, part numbers in 1..count, unique, each size equal to the planned size), `parsePartUrlGrants` (exactly the requested part numbers, method PUT, absolute http(s) URL without credentials, content_length = slice size, one storage origin across batches, optional `storageOrigin` prop), `parseUploadedDataset`. Every reply is also parsed strictly (UI CHECKLIST a).
3. **Return 3 (identity).** The draft key and the stored draft carry organization + project + connection (a draft under another identity is ignored); the inner component is keyed on API base / organization / project / connection / storageOrigin so a prop change discards session, file and draft; an `aliveRef` stops a stale async continuation at its next await; a busy guard stops a double click starting two sessions or two finalizes.
4. **Return 4 (no simulated progress).** A part is counted only after a 2xx PUT of its bytes (a Set of part numbers), or when the real listing names it. The listing is validated (UF3 closed); the PUT method is the literal "PUT".
5. **Return 5 (typed errors, Law 17).** `classifyFailure` treats only known (status, code) pairs as typed: 410 upload_expired; 503 storage_*; 409 upload_incomplete / dataset_version_conflict / upload_session_not_open; 404 not_found; 422 with a known rejection code. Everything else (5xx, 401, 403, 429, non-JSON, unknown code, known code on the wrong status) is retryable and keeps the draft. `dataset_version_conflict` keeps the session open and finalizable under another name (UF6/UF7); resuming a verified session shows a terminal state (UF10); create failures return to a usable form instead of a dead "error" phase.
6. **Return 6 (real-API test).** `apps/web/tests/real_api/ftf_0501_ui_real_api.realapi.ts` + `vitest.real-api.config.ts` (not in the default include) driven by `tests/integration/test_ftf_0501_ui_real_api.py` and the new CI job **`resumable-upload-ui-real-api-integration`** (in `ci-verdict` needs). It runs the component against the real router on PostgreSQL 16 as `sovra_app` and SeaweedFS with parts at S3's 5 MiB minimum (11 MiB = three parts): R1 multi-part upload + finalize; R2 a dropped PUT of part 2, reload (new component, same localStorage), resume re-requests only the missing parts (`part_numbers[0] == 2`, part 1 never re-sent) and finalizes; R3 another organization's path is refused. The Python side then checks, independently, two Datasets whose `verified_sha256` / size equal the bytes the UI picked, both sessions verified, objects of the right size in the bucket, nothing in the other organization, exactly two sessions.

**Survivors (equivalent mutants, kept as defence in depth):**
* `if (!isPositiveInt(body.part_count)) return null`: with the plan check `part_count === ceil(size / part_size)` and positive-int size and part size, `part_count` is already a positive integer.
* `if (origin === null) return null` in `parsePartUrlGrants`: unreachable, the loop runs at least once (an empty request is refused earlier) and sets the origin.
* `!sameId(session.project_id, projectId)` in `finalize`: unreachable, the session state is created only by a reply bound to the same project prop and the component is remounted on a prop change.
* `uploaded.size !== part_count` before "ready to finalize": unreachable on a conformant flow, every missing part is requested and bound to its grant.
(Removing these four guards was not done: they are cheap checks and the sweep treats them as disclosed equivalents.)
Other guards that look redundant (purpose / size / sha / content type / name enum checks) are killed by direct parser tests that call the parser without the later binding.
