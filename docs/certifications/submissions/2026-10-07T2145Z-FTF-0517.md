# FTF-0517 r1 — Group-aware split engine

Scope: `workers/data/group_aware_split_engine.py` (new, pure, no I/O), `tests/tasks/test_ftf_0517.py`, one additive
`ci.yml` step, `docs/spec-matrix.yaml` entry (PROVISIONAL / L1-PROVEN). Path refined from the packet's generic
`services/training-worker/data/` to `workers/data/` (real SOURCE_ROOT, same as the sibling data modules).
Run as CI does: `uv run python3 tests/tasks/test_ftf_0517.py` -> `all checks passed`.

Acceptance: every record gets one of train / validation / development_eval / final_qualification under strategy
`sha256_group_hash_v1`, an explicit seed and ratios, in an immutable SHA-256-bound manifest. Records sharing any
linkage key (conversation, template family, customer case, near-duplicate group), directly or transitively, are one
group (union-find) and never cross roles. A group's role depends only on strategy, seed and its own keys. Negative
acceptance: `verify_manifest` recomputes the hash and independently re-checks group isolation, counts and status; the
engine takes no outcome input, so a final result cannot drive a reshuffle; temporal cutoff keeps post-cutoff groups in
eval roles only; evaluation-preassigned groups never move into train/validation.
