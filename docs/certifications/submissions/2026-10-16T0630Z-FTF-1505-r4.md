## Point by point

1. **F-FAULTS-BEHAVIOURAL.** Every `inspect.getsource` check is gone. `main()` now takes `--root`
   and `--baseline` (defaults: this repository and its committed baseline, which is what CI runs),
   and `test_main_decides_on_every_lane_and_every_completeness_check` runs it for real on disposable
   git repositories (only the live app boot is replaced, because it needs this repository's app):
   - a clean repository passes (`0 blocking -- clean`);
   - a history-only secret raises naming `[history]` (F16);
   - an untracked `reports/` secret raises naming `[artifact]` only (F17);
   - a tracked `docs/` secret raises naming `[source]` (F4 in main);
   - a blocking finding whose own scenario PASSED still raises (F18 -- the round-3 test injected a
     failed scenario, so it could not fail);
   - an upload path outside the artifact roots raises (F19);
   - a production directory with no tracked file raises (F20);
   - a tracked file the source lane never scanned raises (F20b);
   - a failed seeded-recall check raises.
   F21 (artifact canary), F6h (history blob over the bound), F22/F14/F15 (live lane, point 2), F23
   (log sink scan, below) and N14 (pre-redaction recall) each have their own behavioural test.
2. **F-LIVE-POSITIVE-CONTROL.** `scan_live_app_log_samples` now fails unless it sees uvicorn's own
   stderr startup line (`live_app_stderr_captured`), one access-log line per probe, matched as a
   whole tag (`live_app_access_line[<probe>]`), and a fresh canary placed in a URL path (never
   rewritten by the redactor) found by the same scan of the captured output that must find nothing
   else (`live_app_scan_detects_positive_control`; only that exact value is exempt). The OIDC
   callback's unauthenticated error paths are probed: no `code` gives 422 (request validation),
   `code` + `state` matching no login gives 400, each with canaries and with every rule family's
   seed in `code`. The round-3 disclosure that no error path was reachable is removed.
3. **F-ARCHIVE-ZLIB.** Any per-member failure (`zlib.error` included) yields a blocking
   `scan_incomplete` for that member, and extraction continues: the verifier's corrupt-deflated
   probe now reports the bad member and still finds the secret in the next one.
4. **F-ARCHIVE-CORRUPT / OVERSIZE.** An archive that cannot be opened (truncated zip, tar.gz cut in
   half, truncated .gz, a `.gz` name without gzip data) is a blocking `scan_incomplete` (unreadable
   archive), never an outer `return`. A member longer than `MAX_SCAN_BYTES` is a blocking
   `scan_incomplete` (member exceeds scan bound) in zip, tar.gz and .gz. The history lane passes the
   blob's real path for archive recognition: a tar.gz is recognised by name only, and the
   `path@sha` location label hid its extension (a history-only tar.gz was never opened).
5. **F13-SEAM.** No more line windows: every line (and every non-UTF-8 unit) is matched whole. Long
   secrets are found at every one of 451 offsets of a long line (JWT, percent-encoded JWT, 64-char
   `client_secret`, AWS secret key, Slack webhook, base64-wrapped GitHub token, URL password), and a
   JWT in a one-line JSON file is found by the source and history lanes. The one non-linear pattern
   on long lines -- the JWT candidate regex, which restarts at every `-` boundary of a dotless run --
   is replaced by `_jwt_tokens`, an exact linear emulation of the same regex, proven equal by a
   60,000-string differential (0 mismatches). The base64/hex candidate caps are removed: candidate
   runs are disjoint, so decoding all of them is linear, and a cap could only be a detection gap (a
   secret after 3,000 other candidates is now found in a line, a binary unit and the CI-report CLI).
   `test_whole_line_scanning_stays_linear_on_pathological_lines` pins linearity on five
   backtracking-prone shapes.
6. **F-SEEDS-PER-LANE.** `scan_seeded_recall()` (called by `main()`) plants one fresh seed per rule
   family in a disposable git repository: a tracked file, the same base64-wrapped, a zip member, a
   history-only blob (committed, then deleted) and an untracked artifact-root file. It scans them
   with the real source, history and artifact lanes: one `seeded_recall[<lane>][<rule>]` result per
   pair (5 x 16). The log-line lane's recall is `scan_log_samples`, which now also writes each seed
   to an UNREDACTED control sink that must be detected by the same single `scan_line` call that must
   find nothing in the redacted sink (F23 cannot disable one without the other).
