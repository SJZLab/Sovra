## What changed (QUEUE 0c items)
1. Train is tied to the checked identity. The result, error, loading and started state reset during render when the
   org, connection, project or model changes (no committed frame with a stale Train; also not resurrected on switch-back).
   A per-request counter ignores any response (status, error body or JSON) from a superseded request. A 200 whose
   `public_model_name`, `project_id` or `litellm_connection_id` differs from the request is an error with no Train.
2. Strict parse of the frozen `ModelCapabilities` schema: unknown top-level key, missing or ill-typed field,
   out-of-enum `access`/`capability`/`availability`, non-boolean `license_approved` (the string "false" no longer
   enables Train), a dimension in an unrecognised state, or `unknown` with no reason are all typed errors with no Train.
3. VRAM fails closed: `known` needs a finite `tested_gb` and a numeric declared `memory_gb`, and tested >= declared;
   anything else blocks with its own reason.
4. Rows show only what the server returned. No date is borrowed from the discovery timestamp; each row states "no
   evidence date returned by the server"; the tested VRAM value and the reason are in the row.
5. No simulated effect: with no `onTrain` wired, Train is disabled and the click handler reports nothing; "Training
   requested" appears only after `onTrain` returned.
6. Tests pin `credentials: "include"`.
