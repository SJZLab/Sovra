## Same-class sweep
Defect class: constructing a `frozenset`-typed field by iterating a caller-supplied container with
no type check first (bare `str` -> per-character; `None`/non-iterable -> bare `TypeError`), and
membership/equality checks performed without first confirming exact type (enabling an unhashable
value to raise `TypeError` instead of a typed error). `_validated_set` in this module was the only
generator-over-a-caller-supplied-container site in `packages/litellm_client/`. Checked the sibling
module this task's own docstring already cites as precedent, `packages/security/
security_profile_enforcement.py`: its `RouteAuthorization.__post_init__` already guards
`isinstance(self.surfaces, frozenset)` before iterating `surfaces`, and its own `_member` helper
already does `isinstance(value, str)` before any membership test (with an explicit comment: "Type
check before membership: an unhashable value must raise our own error rather than TypeError") --
already compliant with this exact class; no fix needed there. No other dataclass in either module's
package does per-member validation via a generator over an unchecked field.
