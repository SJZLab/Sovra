## Defect found by the new integration test (real, fixed here)
`capture_local_repository` detected drift only by comparing `git status --porcelain` text before/after. An edit to an
already-dirty tracked file or an untracked file leaves that text unchanged, so a file edited mid-capture produced a
TORN snapshot: archive bytes disagreeing with the manifest/`tree_hash`, no error. Reproduced before the fix: 4 FAILs
(in-place edit of a dirty tracked file, of an untracked file, edit between archive build and the final check, and a
real concurrent writer: 15-16 of 40 captures torn).

Fix (`apps/api/app/target_connectors/local_repository_connector.py`, +14 lines):
1. `_build_archive` refuses (`ConcurrentModificationError`) if a file's bytes no longer match its manifest sha256/size.
2. After the existing git-identity check, the content manifest is re-walked and its hash compared to `tree_hash`.
