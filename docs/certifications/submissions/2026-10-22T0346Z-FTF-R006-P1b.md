## Real bugs found and fixed during this task's own development (Law 1: RED before GREEN)

1. **Stale caller-supplied identity status.** `sync_workspace_membership` originally trusted the
   caller's own `identity.status` field instead of re-reading it from the database. A real
   integration test (revoke an identity, then call `sync_workspace_membership` again with the
   caller's now-stale `identity` object) went **RED**:
   `FAIL [R006P1b-int] a revoked identity is refused by sync_workspace_membership -- never
   silently re-added`. Fixed: the function now re-fetches the identity's current status from the
   database by (organization, issuer, subject) on every call, and additionally refuses if the
   caller's `identity.id` no longer matches the freshly-looked-up row (a stale-reference guard,
   also tested directly). Re-ran: **GREEN**.
2. **Unhandled real Argilla username conflict on a concurrent identity-creation race.** A real
   8-thread concurrency test (`section_races`, both `ensure_review_scope` and
   `ensure_reviewer_identity` against a brand-new (org, project)/(org, issuer, subject) pair) hit
   a genuine `ArgillaConflictError: username already exists` from the real fake-Argilla-server
   HTTP layer — uncaught, it propagated out of `ensure_reviewer_identity`. Fixed: a username
   conflict can only mean a concurrent caller is provisioning the exact same deterministic
   identity (the username is `sha256(org|issuer|subject)`-derived, never reused across
   identities), so the function now polls the database for the winner's row (bounded: 20 attempts
   × 50ms) and returns it, rather than treating the conflict as a hard failure. Also added a
   direct test for the bounded give-up path (an always-conflicting fake client wrapper that never
   resolves) to confirm it still raises `ArgillaIdentityError` rather than retrying forever.
3. **A check-then-act race in the fake Argilla server test double itself** (not production code):
   workspace/user/membership creation checked for an existing name/conflict and then wrote, with
   no lock across the `ThreadingHTTPServer`'s per-request threads — the same 8-thread race
   produced two users with the same deterministic username on the fake server before fix #2's own
   retry-poll logic was even reached. Fixed with a `threading.Lock()` around every check-then-act
   section in `argilla_test_support.py`.
4. **A confounded self-attack test.** The first version of the unauthorized cross-org INSERT test
   (self-attack below) reused `world.project1`, which already had a real scope row — the table's
   own `UNIQUE (organization_id, project_id)` constraint could have been silently doing the
   refusing instead of the RLS `WITH CHECK` policy, making the test not actually prove what it
   claimed. Fixed to use a brand-new, scope-free project; re-confirmed genuinely RED when the
   policy is weakened (below), genuinely GREEN on the real policy.
5. **Two real typing gaps found by running `mypy .` repo-wide** (this slice had only been checked
   file-by-file before): `workspace_name_for`/`_username_for` silently hashed a `None` or
   non-`uuid.UUID` `organization_id` into a deterministic-looking but meaningless name — real
   callers already validate this upstream (`tenant_scoped_session`'s own `TenantContextError`
   guard runs first), but the two naming helpers had no defense-in-depth of their own. Added
   direct `isinstance` checks with a RED→GREEN test
   (`test_naming_functions_refuse_non_uuid_and_empty_inputs`). The fake test server's own
   request-body field access (`body.get("name")`, `.get("user_id")`, …) also needed the same
   discipline to satisfy `mypy .` without weakening the checks — fixed to validate before use,
   same as every real HTTP handler in this codebase already does for untrusted input.
