## Finding -> change -> test

1. **MISSING-PG-ROUTE-INTEGRATION.** New `tests/integration/test_ftf_0519_routes_postgres.py` (real
   uvicorn, `sovra_app`, PG16) and CI job `dataset-split-manifest-routes-integration` (classify focus,
   in `ci-verdict` needs). It covers the role/401/403/404/409 matrix, paging, body validation, replay,
   12-way concurrency, approve-vs-reject, review / blocking / blocked-route / saturated (215
   near-duplicates) / tampered / empty-role refusals, a route-locked manifest then a revoked grant
   -> `grant_changed`, and a canary scan of every response body (135+ bodies). The docstring in
   `tests/tasks/test_ftf_0519.py` now names a job that exists.
2. **NO-CI-GATE-STEP.** `gate` now runs `tests/tasks/test_ftf_0519.py` (additive step).
3. **HELD-OUT-SOURCE-DISCLOSED.** Routes apply the certified `_may_see_held_out` rule. For ml_engineer
   every `held_out_evaluation` source is omitted and the final role row keeps only role, purpose,
   record count and role hash (`group_count` omitted; optional in the contract). Tested on the fake
   store (F36-F40) and over real rows with a held-out source on its own connection.
4. **IDEMPOTENCY-KEY-DISCARDED.** Migration 0032 adds `dataset_split_manifest_requests`
   (ENABLE+FORCE RLS, tenant policy, SELECT/INSERT only, unique per org+project+key, digest/action/
   length CHECKs, composite FK to the manifest). The key and digest are written in the lock/reject
   transaction. Same key + digest replays; same key + other digest is 409 `idempotency_key_reused`;
   a refused request leaves its key free. `05-interface.yaml` documents the code.

Advisories A1 / A4 not taken (marked "if cheap"; not cheap).
