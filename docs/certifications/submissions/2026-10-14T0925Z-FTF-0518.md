## Acceptance / negative acceptance
- **Cross-purpose exact / normalized / group / semantic leakage including previous campaigns** — `detect_split_leakage` runs eight methods
  over three pair classes (current cross-role; prior development/final vs current train/validation; prior final vs current final =
  `consumed_final_reuse`). Methods 1-2 reuse FTF-0511 `detect_exact_duplicates`, method 3 FTF-0512 `detect_normalized_duplicates`, methods
  5-8 FTF-0513 `detect_near_duplicates` (zero thresholds, then the configured thresholds with `>=`); the group method is this module's.
  Nothing from 0511/0512/0513/0515/0517 is copied or edited.
- **Privacy-forbidden embedding provider is denied** — before any semantic work FTF-0901 `enforce_effect` (surface `data`): `zero_egress` /
  `air_gapped` (organization, project or job) + external or managed -> `blocked`/`security_profile_route_blocked`; `standard` without a
  covering authorization -> `security_profile_route_not_authorized`; `standard` with one -> `embedding_provider_unavailable` (no external
  embedding client ships: Laws 11 and 17); invalid profile -> `security_profile_invalid_request`; internal -> semantic runs.
  Methods 1-4 are always reported.
- **Unresolved leakage blocks final freeze and training** — `assert_leakage_clear(report, "final_freeze"|"training")` raises
  `LeakageBlockedError` for any open finding; `blocked` / `failed` never clear; reviews (`not_leakage`, rationale 1..2000, reviewer <= 200)
  bind only `review_required` findings; a report whose hash does not cover it, including a self-sealed forgery, is refused.
- **Saturation** — FTF-0513 silently stops at `max_candidates_per_record`; a record reaching `max_semantic_partners` (default 200) makes the
  report `blocked`/`semantic_scan_saturated`, never clear (300 same-role template siblings + one train<->final paraphrase). More than
  `max_findings` is `blocked`/`finding_limit_exceeded`; a pathological bucket costs one pass, not a quadratic walk.
- Report: both record ids, both roles, the method, the reason, the prior label and the scores; no content, text or content hash;
  `finding_id` / `report_sha256` stable under three `PYTHONHASHSEED` values and under shuffled input order.

## Evidence
- Recall: 10,000 records with 200 seeded violations (67 exact copies, 67 case/whitespace variants, 66 group links) -> all 200 pairs found, 0
  invented, 334 findings, ~0.6 s (semantic stage skipped by a blocked route so the run measures methods 1-4).
- Each method detects its seeded pair; whitespace/case/timestamp variant is `text_normalized` only; group link is one blocking finding; a
  paraphrase fires char_ngram + token_jaccard + embedding as `review_required`; same goal + template is `agent_trace_structural`; unrelated
  records are `clear` with every method run.
- Profile matrix (10 routes), threshold boundary (`>=`), prior campaigns, consumed final reuse (exact and near copy), group keys, finding limit,
  input validation (exact types, malformed hashes/content as issues -> `failed`), report integrity (10 unsealed edits + 13 self-sealed forgeries).

## Same-class sweep
- Every sibling detector (0511/0512/0513) already refuses malformed input per record; this module re-checks nothing it can delegate, and turns
  their per-record issues into `LeakageIssue`s and a `failed` report (never silently skipped).
- The silent-cap class (FTF-0513 `max_candidates_per_record`) is the saturation rule above; FTF-0511/0512 have no cap.
- Same-role duplicates are FTF-0511/0512/0513's job (and FTF-0515's gate), not this module's.

## Disclosed
- The hashing embedding is a lexical proxy (FTF-0513 docstring), not a trained model.
- Not checked: prior development vs current development or final, current records in one role, two prior sources against each other.
- Every `consumed_final_reuse` finding is `blocking`, including near copies (a consumed final suite is not reused, Section 9).
- No persistence of findings or reviews (needs a later migration, likely with FTF-0519). No live caller: `proving_symbol` stays blank.
- Caller contract (docstring): FTF-0519 / the training workflow calls this AND FTF-0515 `assert_clear_for_training`.
