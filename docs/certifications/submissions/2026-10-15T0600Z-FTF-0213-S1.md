synthetic `POST /v1/chat/completions` trials, each with a fresh 3-token nonsense enum (disjoint
across trials, from a fixed 64-token vocabulary), the portable `response_format: json_schema`

`UNSUPPORTED_PARAMETER`, `TRUNCATED`, `USAGE_MISSING` (+ the FTF-0210/0213 transport/secret
states). Result carries per-trial `finish_reason`/`completion_tokens`/enum membership/identity/
latency, `max_completion_tokens_observed` and `mean_completion_tokens` (Decimal); both are None
(unknown, never 0) unless every trial reported usage. Reused: `ChatProbeNotAuthorizedError`,
`ChatUsage`, `RouteIdentityState`, `_parse_usage`, `guarded_fetch`, `resolve_secret_ref`. No
migration, route, UI, contract edit, dependency, secret or keyed service. UNWIRED (the
`/models/{id}/probe` route is not live); `proving_symbol` stays blank (FTF-0213 precedent).
No spec-matrix edit: child slices carry no matrix entry (same as #820).

## Decisions where the entry was silent (disclosed)
- Reported `completion_tokens` above the `max_tokens` ceiling with usage present → `MALFORMED_RESPONSE`
  (not success); `finish_reason == "content_filter"` → `CONTENT_FILTERED`; any other non-`stop`
  finish_reason → `NOT_ENFORCED`; missing/non-string `finish_reason` → `MALFORMED_RESPONSE`.
- Precedence: TRUNCATED > CONTENT_FILTERED > NOT_ENFORCED > USAGE_MISSING > over-budget > OBSERVED.
- A hard transport/HTTP failure stops the loop at that trial (no retry without the constraint);
  every non-failing trial runs, so all K are observed.
- Identity is VERIFIED only when all trials resolve to one common model.
- `CONSTRAINED_OBSERVED` is an observation, not proof of the mechanism (see module docstring); the
  real-engine run belongs to FTF-1006.
