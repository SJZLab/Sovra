## What was built
`workers/evaluation/llm_judge_grader.py`:
- `LlmJudgeResult.deployment_fingerprint: str | None = None` -- the real `x-litellm-model-id`
  response header, read only on a genuine 200 (right after the `response.status != 200` check,
  before `_parse_structured_content`), threaded through every subsequent 200-path return
  (`MALFORMED_RESPONSE`, both `MODEL_MISMATCH` branches, `NOT_JSON`, `SCHEMA_VIOLATION`, the final
  verdict). `None` on every other return path (guard/policy failure, 401/403, 400, any other
  non-200 status) -- those all return before the extraction line is ever reached.
- `_deployment_fingerprint_from_headers`: exact lower-case-ASCII header-name match (never a
  substring/prefix match -- same documented header and lookup convention as
  `route_attestation._deployment_fingerprint_from_headers`, duplicated rather than cross-imported
  per this module's own stated "independent module" convention, and because the task's own file
  list forbids editing `route_attestation.py`). The value must be an exact `str` of 1..256
  characters (the width of `model_versions.observed_deployment_fingerprint`, migration 0027) with
  no Cc/Cf/Zl/Zp character; otherwise `None`.
- Every judge request now carries LiteLLM's own documented `"cache": {"no-cache": True}` field
  (the same field FTF-H005's `attest_route` already sends), added as the last key in the request
  body dict -- the golden test confirms every other field is byte-identical to the certified
  round-8 shape once this one key is removed.

## Fault -> RED, confirmed against the real module, restored byte-identical after each
Confirmed first against the genuine pre-fix module (production change `git stash`d, test file kept):
all 32 of the new checks that depend on the new field/behaviour failed for real (`AttributeError:
'LlmJudgeResult' object has no attribute 'deployment_fingerprint'`,
`AttributeError: module ... has no attribute '_deployment_fingerprint_from_headers'`, a genuine
`KeyError: 'cache'` on the golden test, and 4 self-attack checks reporting their own needle text
missing) -- `git stash pop` restored the fix byte-identical, full suite re-ran clean.

Four additional in-shift self-attacks, each applied via a direct text substitution on the real module
on disk, run in a brand-new subprocess (never `importlib.reload`), restored byte-identical after each
(`git diff --stat` empty):

| Fault | Result on the real module (before) | Result under the fault |
|---|---|---|
| Header match forced to always return `None` after the name check (`test_self_attack_header_ignored_fault`) | a valid header gives the real value | `None` -- caught |
| Name comparison widened from exact `!=` to `not in` (substring) (`test_self_attack_substring_match_fault`) | a look-alike name (`x-litellm-model-id-x`) never matches | the look-alike's own value leaks through -- caught |
| Length/Unicode-category validation block deleted (`test_self_attack_length_and_character_check_dropped_fault`) | a 257-char value and a control character are both `None` | both are accepted verbatim -- caught |
| `response.headers` read swapped for the outgoing request's own `headers` dict (`test_self_attack_value_read_from_request_not_response_fault`) | a real response header gives the real value | the outgoing-request dict never carries this header, so the result silently loses the real fingerprint -- caught |
| Extraction call duplicated right after `latency_ms = ...` (before the 401/403/400/non-200 checks) and threaded into the `INVALID_TOKEN` return (`test_self_attack_fingerprint_read_on_non_200_path_fault`) | a 403 response never carries a fingerprint, whatever the header says | a 403 with the header set now leaks it through -- caught |
| `"cache": {"no-cache": True},` line deleted (`test_self_attack_cache_field_dropped_fault`) | every request carries the field | it is silently dropped -- caught |
