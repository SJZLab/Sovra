### 2. OVERFLOW-LONG-NAMES
`overflowWrap: "anywhere"` added to: the case-row `<li>`, the flat field-error-list `<li>`, and the
edit form's `<h3>` heading (which shows the immutable `case_key`). `Field`'s own error rendering
already applies the same style (round-1 precedent, `ui/Field.tsx:48`). Proven at 390 px with a

`ftf_ux06_browser.spec.ts`'s `OVERFLOW-LONG-NAMES` test and in every one of the 40 state × locale
× scheme combinations' own overflow check.

### 3. FOCUS-LOST-TO-BODY
A new `FocusableAlert` component (`tabIndex={-1}`, `role="alert"`, focuses itself on a `signal`
prop change) replaces the three bare `<p role="alert">` elements (list/import/edit). `signal` is a
counter bumped in the same call as the message (`raiseListError`/`raiseImportError`/
`raiseEditError`), so a *repeat* failure with the identical message string still re-focuses the
alert (a naive `useEffect` keyed on `message` would not fire when the string is unchanged — this is
exactly the "16 of 24 faults stayed GREEN" class the verifier flagged). Proven in real Chromium
(`ftf_ux06_browser.spec.ts`, 2 tests) and jsdom (`ftf_ux06.spec.ts`, 4 tests, including the
identical-message repeat case) with a direct mechanism-level reproduction (a plain `<p>` with no
`tabIndex` cannot take programmatic focus — `document.activeElement` stays `BODY`).

### 4. NOT-BILINGUAL
- **"Failed to fetch" / network reason leak**: `networkReasonDisplay` maps the three well-known
  fetch()-level browser messages (Chrome/Firefox/Safari) to a translated "server could not be
  reached" phrase under `locale="ar"`; an unrecognized reason falls back to the existing
  `errUnknownReason` phrase rather than showing raw English. The English default is byte-identical
  to round 1 (verified: `ftf_0602.spec.ts`'s existing network-error assertions still pass
  unchanged).
- **JSON-parser message on a non-JSON 200**: `loadPage`/`handleImport`/`handleSave` now catch
  `response.json()` separately and show the existing localized "malformed" message instead of
  letting the browser's own `SyntaxError` text fall through to the generic network catch (which
  was the actual leak — the pre-fix code had no dedicated catch around the ok-path `.json()`
  call). Proven for all three operations, both locales (`ftf_ux06.spec.ts` ×4, plus the browser
  spec's list-load case).
- **Unknown server detail code**: unchanged at the English default (still falls through to the
  raw `detail` string, same as round 1); under `locale="ar"` an unmapped code now degrades to the
  generic translated `errGeneric` message via the existing `ERROR_DETAIL_KEY` fallback path,
  rather than leaking the raw snake_case code — not separately pinned this round (already covered
  by the field/code mapping below for the one place the module actually surfaces a raw code to the
  user: the field-error list).
- **Raw field codes and names** (`too_long`, `required`, `group_key`, etc.): `fieldDisplay`/
  `codeDisplay` translate the server-returned field name and validation code for
  `locale="ar"` only, via `FIELD_LABEL_KEY` (reusing the existing `fieldCategory`/`fieldSeverity`/…
  translations) and a new `FIELD_CODE_KEY` catalogue. **The default English locale keeps the exact
  raw text round 1 shipped** — verified directly: `ftf_0602.spec.ts`'s own certified assertion
  `toContain("Row 1 / group_key: required")` still passes unchanged. An unmapped field or code
  falls back to the raw value under Arabic too (disclosed, not hidden — same fallback discipline
  `ERROR_DETAIL_KEY` already uses; pinned by its own NEGATIVE test).
- `<bdi>`: not added. This screen never renders free-form user-authored *prose* inline with
  system text the way the UX02/UX05 areas do (`case_key`/`category`/`group_key` are short technical
  identifiers, not names needing bidi isolation, and they already sit inside their own `<span>`
  with `overflowWrap: anywhere`); recorded as a severity-2 decision, not silently dropped.

### 5. ERRORS-NO-RECOVERY

state's `action` (previously `null`) is now a real `Button` that focuses the import textarea.
Proven in both jsdom and the browser spec.

module docstring, now narrowed to exactly these six fields instead of all ten.
