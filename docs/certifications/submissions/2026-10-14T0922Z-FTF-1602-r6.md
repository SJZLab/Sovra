## 1. F7-CREATE-NOW-VALIDATED-LATE

`create_backup` already validates `now` (type + `utcoffset() is not None`) before making a single
call to either `source` or `target` — the hazard named is a bad `now` discovered only after blobs
are already written WORM-retained on a real server, which can never be undone. Added, both
suites: a table of bad `now` shapes (naive, `tzinfo` set but `utcoffset() is None`, `str`, `int`,
a `datetime` subclass) against a call-counting double (`CountingStore` / unit,
`CountingStore(S3ObjectStore)` / real) wrapping both `source` and `target`, asserting the typed
refusal **and** zero calls on either store, plus a negative control (a genuine `now` does proceed
and does touch both stores — proving the zero-calls assertion is real, not an always-zero double).

`test_round6_now_validated_before_any_store_call` (unit);
`test_now_validated_before_any_store_call_on_real_server` (real).

Since the check fires before any network call, the real-suite version of this test needed no
working object-write path and ran clean against the live local SeaweedFS boot described below.

## 3. G1/G1b — rebuilt on the Q2 shape

Round 5's ABA test (`test_pinned_record_read_ignores_a_transient_unretained_swap`) hooked
`get_version` to inject the forged content. A real regression that changes *which* method
`_load_record` calls for the content (`get_latest` instead of `get_version(pinned_id)`) never
invokes that hook at all — confirmed this round by applying exactly that one-line mutation to
`scripts/object_storage_backup.py` and re-running round 5's own test unmodified: its **primary**
assertion ("verify reads the pinned version's real content... `result == record`") stayed green;
only the separate, self-referential `FaultyLatestInsteadOfPinned` double (which directly
implements the hypothetical bug rather than letting the real mutation trigger it) went red. That
is the "G1 reddens the real suite only incidentally" finding.

Rebuilt both suites on the Q2 shape: a forged version is PUT the **first time the record is
listed** (`list_versions` — always called first, regardless of which method is used to read the
content next) and DELETEd the **first time retention is checked** (`retention_until` — always
called right after the read, before the re-list). This reddens through whichever method
`_load_record` actually uses, because the hook is on the two calls every code path makes, not on
the content-read method's name.
