single-file CLI now live in a new module with **zero third-party imports** (`test_secret_rules_

5. **F-SCOPE/F-BINARY** -- fail closed, never omit silently:
   - Non-ASCII tracked filename: `iter_tracked_files` now uses `git ls-files -z` (NUL-separated,
     unquoted). Plain `git ls-files` applies `core.quotePath` by default and octal-escapes a
     non-ASCII filename (`"caf\303\251.txt"`), which then never resolves back to the real file on
     disk -- silently skipped, zero signal. Reproduced directly
     (`test_non_ascii_filename_is_scanned_not_silently_skipped`): the quoted form is shown not to
     match the real filename; the fixed `-z` form does, and the secret in that file is found.
   - Oversized content: `_read_bytes_bounded` now detects truncation (reads `MAX_SCAN_BYTES + 1`,
     compares) and a truncated unit is a blocking `scan_incomplete` finding
     (`test_oversized_content_is_a_blocking_scan_incomplete_finding`); same for a history blob via
     `_iter_history_blob_contents`'s own declared-size comparison.
   - Corrupt archive member: round 2 wrapped the ENTIRE member-extraction loop in one try/except,
     so a corrupt member (bad CRC) aborted every later member too. `_iter_archive_members` now
     catches per-member read errors and yields `(name, None)` -- a fail-closed signal the caller
     turns into a blocking `scan_incomplete` finding -- and CONTINUES to the next member.
     `test_corrupt_archive_member_does_not_abort_later_members` builds a real 3-member zip with
     the middle member's stored bytes corrupted (one flipped byte -> CRC mismatch) and shows the
     member AFTER it is still read by the fixed code, while an explicit "whole loop, one
     try/except" fault reproduction abandons it.
   - Archive members in history-only blobs: round 2's `scan_history` never called
     `_iter_archive_members` at all (only `scan_source`/`scan_artifact_roots` did). A shared
     `_scan_content_and_members` helper now backs all three lanes;
     `test_archive_member_in_a_history_only_blob_is_scanned` commits a zip, removes it in a later
     commit, and confirms the history lane still finds the secret inside the (now history-only)
     archive member.
   - `assert_scanned_set_matches_tracked_files`: the set of paths `scan_source` actually processed
     must equal every regular (`100644`/`100755`) tracked file `git ls-files -s -z` reports --
     fails closed on any silent gap. Wired into `main()`, proven against both a clean real repo
     and an artificially-shrunk scanned set.

6. **Redaction** -- `SecretFinding.to_dict()` now omits `value_sha256` entirely (returns `None`)
   for a blocking (NEW, unreviewed) finding; a baselined (already-reviewed) finding keeps it. An
   unsalted `sha256(value)` of a low-entropy secret (a short DSN password, say) is
   dictionary-reversible in seconds -- printing it for a finding nobody has reviewed yet would
   itself leak. `test_blocking_finding_omits_value_sha256_...` proves both the fix and, via the
   explicit `dataclasses.asdict` fault counterpart, that the OLD shape would have printed it. The
   internal baseline-matching fingerprint (`sha256(rule NUL value)`) was already never printed
   (confirmed: only `value_sha256` appears in any printed/stderr output) and stays a stable,
   deterministic value -- it must match a value a human reviewer committed into
   `secret_scan_baseline.yaml`, so it cannot be randomly salted per run without breaking every
   existing baseline entry; this is disclosed rather than silently left as an unexplained
   deviation from the return item's "may use a keyed/salted digest" suggestion.

8. **The 2026-10-15T08:43Z ruling (F2b)** -- `scan_history`/`iter_history_blob_ids` take an
   explicit `refs`/`scope` parameter. `main()`'s default (and the unmodified `secret-scanning`
