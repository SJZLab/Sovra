## What changed in production

`_is_query_param_name` is now: last word (separator + camelCase split) is a name -> redact; else
read the name with every `_ - .` stripped and lowercased and **redact if it ENDS in a credential
name, unless the whole stripped name is in the closed `_BENIGN_NAMES` list** (monkey, decode,
barcode, estate, compass, bypass, possession ... 38 words). The 21-word `_COMPOUND_PREFIXES`
vocabulary, the DP chain matcher and the 64-char bound are gone (QP-GLUED-VOCAB). `totp`, `hotp`,
`sessid`, `phpsessid` were removed from `_QUERY_PARAM_NAMES`: they end in `otp`/`sid`, so listing
them was redundant (their per-name fault stayed GREEN; they remain test inputs).

1. QP-CASE-SPLIT-SEPARATOR: `mfa_CodE`, `request_sTaTe`, `connect.sId`, `foo-kEy`, `x_cOdE` -> redacted
   (30 prefixes x `_ - .` x 17 names x 3 random spellings x 2 positions, on `redact_text`).
2. QP-GLUED-VOCAB: 30 test-owned prefixes (mfa, connect, service, php, x, sms, device, signing,
   recovery, hmac, ...) x 17 names x 5 glue styles x 2 positions, plus 20 realistic names
   (mfacode, smscode, devicecode, signingkey, connectsid, recoverycode, hmacsig ...) in 3 cases,
   on `redact_text` and on the logging path (`_Harness`). The prefix lists are written in the test,
   nothing is derived from the implementation.
3. QP-SEPSTRIP: `aUtH_cOdE`, `SeSsIoN-kEy`, `sEsSiOn.KeY` and a separator cut inside the final
   name (`co.de`, `k_e_y`, `s-i-d`, every cut position, every separator) -> redacted.
