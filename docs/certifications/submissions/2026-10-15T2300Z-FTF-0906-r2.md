# FTF-0906 round 2 -- verifier-soundness fixes (PROVISIONAL, L1-PROVEN, not certified)

Branch `relay/FTF-0906-r2`, QUEUE.md Active item 0j (Control-plane ruling landed on the
not-yet-merged `[CERT]` PR #847, commit `e2f20ee`). Verifier findings reproduced first (`23056b0`,
PR #832): the FTF-H006 enforcement layer itself is sound over real sockets (alternate ports,
non-allowlisted/decimal/`::ffff:`/`::1` IPs, `localhost.`, userinfo URLs, a DoH host, redirects to
the sink, `HTTP_PROXY` all denied for real); the problem is entirely in the *verifier*
(`packages/security/egress_capture_verification.py`) that turns that real evidence into a
pass/fail report. This round fixes all 12 required points.

Files touched (matches the round's own declared scope): `packages/security/
egress_capture_verification.py`, `tests/tasks/test_ftf_0906.py`, `tests/integration/
test_ftf_0906_egress_verification.py`, `.github/workflows/ci.yml` (one additive gate step).

## Point-by-point

1. **UNATTRIBUTED-LEAK-IGNORED / UNPLANNED-EGRESS-IGNORED.** `verify_egress` now computes
   `plan_flow_ids` up front and flags two report-level conditions that force `status="failed"`
   regardless of every individual flow's own verdict: (a) `unplanned_evidence` -- any
   enforcement/connection-log/packet-capture/attributed-inspection record naming a `flow_id` this
   plan never declared (`unplanned_egress_evidence` code); (b) `unattributed_leak` -- any
   `PlaintextInspection` with `canary_found=True` and `flow_id=None` (a whole-store, not
   per-flow, inspection -- e.g. a shared access log) (`unattributed_canary_found` code).
   `_aggregate_overall_status` gained `unattributed_leak`/`unplanned_evidence` keyword params that
   always win over every other rule. Tests: `test_unattributed_leak_and_unplanned_evidence_fail_
   the_whole_report` (direct, through `verify_egress` itself) plus the `_aggregate_overall_status`
   kwargs tests. Fault: covered by the direct tests' own structure (removing either flag's `if`
   check is the same class as the mutation rows below); the aggregator kwargs are exercised
   directly rather than through a module-mutation regex, since they are the aggregator's own new
   parameters, not a line to delete.

2. **CALLER-NARROWED-COVERAGE.** `EgressPlan.__post_init__` now refuses any `required_stores` that
   does not include `_MANDATORY_REQUIRED_STORES = {"application_log", "error_path", "artifact"}`
   (`required_stores cannot omit the mandatory log stores [...]`). `workflow_history` stays
   separately, deliberately optional (always forces `partial`, never silently "covered"); `
   controlled_destination`'s own coverage is already forced per-flow by the allow branch's
   positive-control check (point 4), so it is not added to the mandatory set. Every existing test
   that previously narrowed `required_stores` below these three stores was updated to supply real
   (clean) inspections for them. Test: `test_required_stores_cannot_omit_mandatory_log_stores`.
   Fault: `MUTATIONS[8]` (`narrowed_coverage_rejected` probe) removes the guard and shows a
   previously-refused narrow plan now constructs.

3. **FABRICATED-INSPECTION.** Scoped to where the gap actually is: the integration test's
   `application_log` inspection asserted "clean" with no scan at all, while the *shared* log
   buffer it would have scanned still held the deliberately-leaked canary from the buggy-error-
   path demonstration a few lines above it (reused buffer, not the real access-log content).
   Fixed by snapshotting the real access-log text (`real_access_log_text`) immediately after flow
   D, *before* the error-path demo reuses the buffer, then actually calling
   `scan_store_for_canaries` against that snapshot with a real `CanaryPlacementLedger`, asserting
   `found == frozenset()`. Also added explicit `ledger.assert_leak_test_complete()` calls (and a
   `check(...)` on them) after the `error_path` and `artifact` scans, so the integration test
   proves the *declared* coverage was exhaustive, not merely that one scan happened not to raise.
   `verify_egress` itself keeps taking `PlaintextInspection`/`PacketCaptureObservation` as plain
   dataclasses by design (the module's own docstring: "needs the same fact as data, not only as an
   exception a caller might have already caught" -- a pure function tested with synthetic evidence
   at the unit level is the point, not a gap); no production signature change here.

4. **VACUOUS-POSITIVE-CONTROL / ALLOW-FLOW-IGNORES-ENFORCEMENT.** The allow branch's `arrived`
   check is now a single conjunction: `enf.decision == "allow" and client_log.outcome ==
   "connected" and dest_log.outcome == "connected" and dest_inspection is not None and
   dest_inspection.canary_found`. Previously it only checked `dest_log.outcome == "connected"` and
   that *some* inspection record existed (`inspected=True`), never reading `canary_found` at all
   and never cross-checking enforcement/client state against the destination's claim. Tests:
   `test_allow_flow_enforcement_client_destination_must_agree` (the finding's own literal scenario
   -- enforcement deny + client refused while destination claims connected) and every existing
   `_passing_allow`-based test updated to set `canary_found=True` (the fixture now documents why).
   Fault: `MUTATIONS[9]` removes the `enf.decision == "allow"` conjunct and shows a previously
   `failed` mismatched-enforcement flow now passes.

5. **ENCRYPTED-CAPTURE-EVADABLE.** `has_real_inspection = any(insp.inspected for insp in
   flow_inspections)` replaces the old `not flow_inspections` check, so a `PlaintextInspection`
   with `inspected=False` padded into the tuple can no longer "corroborate" an encrypted capture.
   Test: `test_encrypted_capture_is_not_satisfied_by_an_uninspected_dummy_record` (both allow and
   deny classes). Fault: covered by `MUTATIONS[2]` (the branch itself) re-targeted at the new
   variable name; the specific `inspected=False` bypass this point closes is a dataclass-level
   invariant interaction proven by the direct test (an uninspected record existing does not change
   `has_real_inspection`'s truth value the way `flow_inspections` alone used to).

6. **UNOBSERVABLE-AS-NOT-SEEN (Law 17).** Added `"unobserved"` to `LOG_OUTCOMES`. A new branch,
   checked right after the missing-evidence check and before the encrypted-capture/deny/allow
   branches, maps `dest_log.outcome == "unobserved"` to `status="incomplete"`,
   `codes=("destination_unobserved",)` -- never a confirmed `not_seen` (deny-passes) or a
   confirmed failure claim. The integration test's flow D (`169.254.169.254`, a real reserved
   address this sandbox does not own and cannot run a listener on) now reports its destination as
   `"unobserved"` instead of a hard-coded `"not_seen"` it never actually checked; flow C (a real
   HTTP server on `127.0.0.2` this sandbox *does* own and *can* observe) is unaffected -- its
   `not_seen`/`connected` claim stays real. Also closes the integration test's second half of this
   finding ("enforcement decisions/codes are hard-coded"): flows C and D now capture the real
   `OutboundGuardError`/`OutboundPolicyError` and use `str(exc)[:200]` as the `EnforcementObservation.
   code`, never a guessed literal. Test: `MUTATIONS[7]` (`unobserved_destination` probe) removes
   the branch and shows the destination's own real-but-unobserved claim falls through to a
   different status/code.

7. **SKIP-EXIT-0.** The integration test's missing-tool guard now `sys.exit(1)` (documented as a
   Law 17 fail-closed decision -- an environment that cannot run the real-TLS proof must not look
   green) instead of `sys.exit(0)`. GitHub Actions' `ubuntu-latest` runner has every required tool
   (confirmed: this sandbox does too, and the full integration suite was run for real against real
   loopback sockets and a real generated CA -- see "Real CI equivalent" below), so this path is not
   expected to fire in CI.

8. **ERROR-PATH-LEAK-NOT-IN-REPORT + scanner gaps.**
   - The real buggy-error-path leak this test already caught standalone (`leak_was_caught`) is now
     also fed into `verify_egress` on its own small plan (`ftf-0906-error-path-leak-demo`, an
     allow flow modeling the request to sink A plus a deny control flow) with a real
     `PlaintextInspection(store="error_path", ..., canary_found=True)` -- asserted
     `status == "failed"` and `codes == ("canary_leaked",)`. The main A/B/C/D report stays leak-
     free, as designed.
   - A fragmented canary split across two *real* headers is now actually checked against the
     bytes sink A really received (`a_received_headers["X-Canary-Frag-1"] +
     ...["X-Canary-Frag-2"] == marker.value`), not merely sent and forgotten.
   - `scan_store_for_canaries` gained `_needles_for_encoding`: for `hex`, both the canonical
     lower-case `bytes.hex()` form and its upper-case variant are checked (a real intermediary can
     re-case hex before it reaches a log); for `url`, the canonical `quote()` form (always
     upper-case percent-escapes) plus a lower-cased-percent-escape variant (what a real reverse
     proxy/log shipper can re-emit) -- the previous "upper-case the already-upper-case base" code
     was a silent no-op, found while writing the direct test. Tests:
     `test_scan_finds_case_variant_hex_and_url_encodings` (checks `_needles_for_encoding` directly,
     then a real `scan_store_for_canaries` call against each variant, both raising
     `CanaryLeakedError`).

9. **REPORT-UNBOUND.** `EgressVerificationReport` gained `policy_digest: str`, `scope: str` and
   `inspected_stores: tuple[str, ...]` fields, all copied from the plan/computed coverage and all
   bound into `report_sha256` (`_report_sha256`'s canonical JSON payload now carries
   `policy_digest`, `scope` and a sorted `inspected_stores` alongside the pre-existing fields).
   Test: `test_report_binds_policy_digest_scope_and_inspected_stores` (checks the new fields'
   values, then tampers only `plan.policy_digest` via `object.__setattr__` on a second otherwise-
   identical plan and shows `report_sha256` differs). Fault (F7): `MUTATIONS[12]`
   (`hash_changes_with_verdict` probe) removes the `"flow_verdicts"` key from the canonical dict
   and shows two reports that differ *only* in `flow_verdicts` (every other report field --
   status, codes, not_exercised, inspected_stores -- made identical by construction, isolating
   exactly this one input) now hash identically.

10. **GATE-STEP-MISSING.** Added one additive step to `.github/workflows/ci.yml`'s `gate` job,
    immediately after the existing FTF-0905 step: `uv run python3 tests/tasks/test_ftf_0906.py`.
    (The `egress-verification-integration` job already ran the integration suite; the unit/fault
    suite previously ran only inside the mutation-gate job, which only fires on `[relay]`-titled
    PRs -- this step makes it run in every `gate` run.)

11. **Faults F3/F4/F5/F7.**
    - F3 (deny flow ignores capture `canary_found`): already present in round-1 code (`canary_seen
      = any(...) or (capture is not None and capture.canary_found)`), but no test exercised it.
      `MUTATIONS[10]` (`deny_capture_canary_only` probe: a deny flow with no plaintext inspections
      at all, only an unencrypted `PacketCaptureObservation(canary_found=True)`) removes the
      `or (...)` clause and shows a flow that should fail `unauthorized_transfer` now passes.
    - F4 (uninspected stores count as covered): `MUTATIONS[11]` (`uninspected_counts_as_covered`
      probe) removes the `if insp.inspected` filter from the `inspected_stores` set comprehension
      and shows a report with every mandatory store genuinely uninspected (`inspected=False`)
      flips from `incomplete` to `passed`.
    - F5 (uninspected destination as positive control): **reviewed equivalent under this round's
      own fix, not a live gap** -- disclosed rather than silently dropped. Point 4's `arrived`
      check now additionally requires `dest_inspection.canary_found`, and `PlaintextInspection.
      __post_init__` already refuses `canary_found=True` with `inspected=False`
      ("a canary cannot be found at a store never inspected"). So any `dest_inspection` the
      `next(...)` lookup could select with `inspected=False` necessarily has `canary_found=False`,
      which already fails the conjunction on its own -- the `and insp.inspected` clause in that
      lookup is now dead weight, not a live bypass. Kept for defensive clarity (the dead-weight
      analysis is itself a fact about the *current* code, not a guarantee against a future
      refactor); no fault row added for it since no observable mutant exists to kill.
    - F7: see point 9.

12. **tmp cleanup + advisory.** `atexit.register(shutil.rmtree, _TLS_TMP, ignore_errors=True)`
    added right after the directory is created, so the CA private key and the response-artifact
    file it holds are deleted at process exit (verified empty after a real local run: `ls
    /tmp/ftf-0906-tls-*` -> no such file). Advisory on `docs/implementation/task-packets/
    FTF-0906.md` (generated, outside this round's declared file list) left untouched, disclosed
    rather than silently regenerated outside scope.
