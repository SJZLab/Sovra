## Diagnosis

Every survivor sits on a field validated at construction by this module's own `_member`
(or, for `placement.encoding`, FTF-0905's own `_member` in `canary_secret_generator.py`)
against a closed tuple whose members are already lowercase and whitespace-free (`"deny"`,
`"connected"`, `"not_seen"`, `"controlled_destination"`, ...). Through the normal public
constructors, `.strip().lower()` applied to any of these fields is a true no-op, so the
mutant is unobservable via normal construction -- not a missing test for a real bug.

One survivor (`_hex64`'s per-character loop, line 155 pre-fix) was true under *every*
possible input, by construction: the loop already iterates `value.lower()`, so each `c` is
pre-lowered; `.strip()` on a non-whitespace char is a no-op, and on a whitespace char
yields `""`, which is `not in _HEX64` exactly like the original whitespace char was.
Mathematically unkillable by any test. Fixed by replacing the loop with a single
`re.fullmatch` (no behavior change -- case-insensitive hex still accepted, original value
still returned), which removes the AST shape the mutation operator targets.

The other ten were killable, but only by proving the *downstream* comparison itself stays
exact even if a frozen dataclass's own invariant were ever violated elsewhere (a future
refactor that skips `__post_init__`, e.g.) -- defense-in-depth, same class as the FTF-0503
precedent's `dataclasses.replace`-bypass test for `Slot.kind`. `object.__setattr__` is the
only way to get a non-canonical value past a frozen dataclass's own `__post_init__`; each
new test constructs a real, valid instance first, then tampers exactly one field.
