## Route chosen, and why (CLAUDE.md default-resolution rule; the Control plane delegated this choice)

The r2 park listed three options. This round takes **option 1**:
- the network and process guard now covers *every* adapter call;
- r2's round-3 items 2-4 are closed;
- process-level egress below the interpreter is left to the worker's OS network boundary, and disclosed.

Reasons:
- **The integration form is already fixed.** `REFERENCE_REPOSITORIES.md` names Inspect AI as a *pinned evaluation-worker package* that the Factory wraps with its adapter, policy and evidence layer. Neither QUEUE.md's P3 design nor the packet names a sandbox mechanism.
- **Option 3 would change the integration form.** Running the bridge in a child process under `unshare -n` adds a process-isolation design that nothing in the architecture specifies. CLAUDE.md forbids changing the integration form.
- **Option 3 may not be runnable.** Unprivileged user namespaces are restricted on the CI runner image (Ubuntu 24.04, AppArmor), so the mechanism might not work there.
- **Option 2 is not the relay's to take.** It is a certification decision, and it would leave the findings open.
- **Option 1 meets the DoD bullet as written.** "An outbound call happens during a run" → RED is enforced at the interpreter level, from both C and Python entry points. The run-level OS boundary belongs to deployment and the sealed worker (FTF-H020, §77), which the packet already lists as separate.

The pre-reviewer accepted the route. It noted, as an advisory, that no Control-plane ruling on deferring the OS boundary has been recorded yet; one should be recorded at L2.

Ruling on `route_fingerprint` (r2 item 3), which the pre-reviewer accepted:
- The reference FTF-04A26 adapter's per-case `route_fingerprint` is `sha256(tool_name, tenant)`. It legitimately differs from tool to tool, so requiring the same value across cases would wrongly refuse a correct run.
- Each case's whole outcome, route fingerprint included, is instead pinned for the whole run. After the run every case is collected again and must be exactly equal; otherwise the run gives `runtime_identity_changed`.
- The run-level route identity is pinned through the attestation's `model_binding_fingerprint` and `gateway_config_fingerprint`. These are re-checked before every case and after the run.

## What changed in r3

All changes are in `workers/evaluation/adapters/inspect_adapter/{runtime_bridge,case_adapter}.py`, `tests/tasks/test_ftf_r004_p3.py` and `tests/integration/test_inspect_target_bridge.py`.

**1. Guard (r2 item 1).** `_NetworkGuard` now spans the whole run: `describe`, `attest`, `bind_bridge_hook`, every case, the final identity re-check and the post-run re-collection. It has two parts.
- **An interpreter audit hook.** The hook is raised from the C implementation, so it also sees the raw `_socket` type, `os.system`, `os.posix_spawn` and `ctypes`. While a run is active it refuses:
  - every non-AF_UNIX `socket.__new__` (including `fileno=` wraps and `accept()`), `connect`, `sendto` and `sendmsg`;
  - every name lookup (`getaddrinfo`, `gethostbyname(_ex)`, `gethostbyaddr`, `getnameinfo`);
  - every process start and `ctypes` foreign call. The one exception is the pinned Inspect release's own three read-only git lookups (`inspect_ai._util.git.git_context`), matched by the exact argv and the real `git` executable.
- **A start-time check.** A run refuses to *start* while the process holds any connected non-AF_UNIX Python socket: plain, raw `_socket` or TLS. Such a socket could otherwise carry data out through sends that no hook sees.

Any attempt refuses the run, even if the adapter caught the error. The Python send and lookup monkeypatches from r2 can no longer be reached, so they are removed.

**2. Per-case results (r2 item 2).**
- `invoke` and `collect_outcome` results must be exactly `AdapterInvokeResult`, with field types checked.
- Their `__post_init__` invariants are re-run on a rebuilt copy, so a frozen result edited with `object.__setattr__` is refused.
- `describe`, `attest` and `preflight` are type-checked too. Any failure gives `adapter_contract_violation`.

**3. Route and outcome pinned for the run (r2 item 3).** `recheck_collected` (described in the ruling above).

**4. Provenance (r2 item 4).**
- Members of the loaded-suite registry are held with a sha256 content digest covering the set, every case field and every Sample (`model_dump_json`).
- Membership recomputes the digest, and only the exact `SuiteCaseSet` type can be a member. It is re-checked after the run.
- So `object.__setattr__` and in-place Sample edits are refused, before the run or during it.

**5. Removed: the r1 opt-in `--faults` probe table.**
- CI never ran it, and it had been broken since r2: 15 of its rows no longer applied to the code.
- The uncapped mutation gate and the table below replace it.

## ADVISORY (non-blocking, from the pre-review)

1. A small race in `_NetworkGuard.__enter__`: a background thread could open a socket between the scan and the guard activating.
2. The pre-run scan refuses runs while the worker holds any connected Python TCP/TLS socket, including unrelated pools. This fails closed, but the bridge should run in a process without such sockets.
3. `Popen(executable=None)` raises a `TypeError` inside the hook. The process does not start, so this is fail-closed, but it is not counted as an outbound attempt.
4. Concurrent runs raise a bare `RuntimeError` from Inspect, not a `BridgeError`.
5. While a run is active, the guard applies to the whole process.
6. The OS-boundary deferral (park option 1) should be recorded as a Control-plane ruling at L2.
