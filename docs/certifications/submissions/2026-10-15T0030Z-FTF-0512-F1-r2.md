## Production change (workers/data/normalized_duplicate_detector.py)

1. **F1-NFKC-DIGIT-MERGE (fixed):** `_fold_look_alikes` segments every category-No/Nl character
   (superscript/subscript digits, vulgar fractions, circled numbers, Roman numerals) out of the
   string before calling `unicodedata.normalize("NFKC", ...)`, so they are never folded into an
   ASCII digit — a character of its own already breaks any composition/decomposition sequence it
   would otherwise be part of, so this changes nothing about how the surrounding text folds.
   Fullwidth-letter folding (round 1's original purpose) is unaffected.
2. **F1-NFKC-QUADRATIC (fixed):** `_assert_safe_combining_run` refuses any run of combining
   (non-starter, `unicodedata.combining(char) != 0`) code points longer than 30 — UAX #15's own
   Stream-Safe Text Format bound — as a typed `NormalizedDuplicateDetectionError`, reported per-row
   as `unknown_content` by `detect_normalized_duplicates`, never processed at unbounded cost. This
   sandbox's own `unicodedata` does not reproduce the verifier's 99.7s timing at all (confirmed:
   the same pathological shape normalizes in ~1.2s here on 3.11 and ~0.2s on 3.12) — the fix is a
   behavioural bound, not tuned to one CPython build's own timing.
3. **Detector version (new):** `_DETECTOR_VERSION = 2` is mixed into the hashed document
   (`{"detector_version": 2, "messages": [...]}`), so this and any future normalization-semantics
   change never silently reinterprets an already-persisted digest (FTF-0515 evidence_digest,
   FTF-0516-P1 issue_id).

Requalification gaps (tests only — production already preserved these fields byte-for-byte):
4. **F1-CF-HANDPICKED (test fixed):** new sweep over all 163 real Cf code points from `unicodedata`
   directly, replacing reliance on the 8-character `INSERTED_FORMAT_CHARS` sample (which exists for
   position coverage, not exhaustiveness).
5. **FTF-0512-TOOL-ID (test fixed):** new checks + faults FG2/FI/FJ/FK, each isolating exactly one
   field (tool_calls[].id, tool_calls[].name, a message's own `name`, a tool message's own
   `tool_call_id`) so a case-normalizing mutation of that field alone is caught — the tool_calls[].id
   check uses a conversation with no separate `tool_call_id` field, since that field would otherwise
   mask a mutation scoped only to the tool_calls entry.
