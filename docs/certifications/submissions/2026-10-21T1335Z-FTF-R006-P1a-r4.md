## Findings
1. TLS-LATE-HANDSHAKE-NO-DEADLINE (R006P1a-11): `wrap_socket` detaches the raw socket, so a watchdog
   firing mid-handshake had nothing to shut down and never fired again. The dead `_raw_sock` path is
   removed. The watchdog now sets a per-connection `_deadline_expired` event BEFORE it aborts, and both
   pinned connection classes check it right after the socket is assigned (`_refuse_if_deadline_expired`),
   raising before any request or status line/header read. Set-then-abort / assign-then-check means
   either the abort saw the socket or the check sees the flag.
   Real-socket test: a TLS server drips its handshake (each gap < the read timeout) and the client's
   connect is slowed so the handshake outlives the watchdog; the handshake completes after the deadline,
   then the status line drips byte by byte. Ends `OutboundGuardError` in ~0.6 s.
2. KEY-ECHO-USERNAME-NAME-UNPINNED (R006P1a-10): invalid username / workspace name carrying the key
   (`[key]`, `{key: 1}`, `[key]`) through create_user / ensure_workspace / create_workspace: the key is
   absent from every exception. G21/G22 (rejection messages that echo the value) turn the probe RED.
