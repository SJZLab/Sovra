# FTF-0504 round 3 — CSV importer (PROVISIONAL, L1-PROVEN, not certified)

Branch `relay/FTF-0504-r3` (PR #786), lane B. Contract: QUEUE.md Active 0c (the Control-plane return of 2026-10-14T06:52Z).

## Return items
1. **UTF8-SIG-INVALID-ENCODING-LOCATOR** — fixed. `_valid_prefix` no longer trusts the codec's error offset (a `utf-8-sig`
   decoder reports it after the BOM it strips, so the cut was 3 bytes short on the first chunk). It searches for the longest
   prefix that decodes (if a prefix decodes so does every shorter one), from a copy of the decoder as it was before the chunk.
   Tests: `test_invalid_bytes_are_located_identically_at_every_split_point_for_every_encoding` (utf-8, utf-8-sig, utf-16-le,
   utf-16-be: every two-piece split of a multibyte document with CR / LF / CRLF endings, plus 1-byte, 7-byte and 1 MiB
   chunkings), `test_a_structure_error_just_before_a_bad_byte_wins_at_every_split_point` (the `ok,"x"y\xff` flip),
   `test_held_over_bytes_do_not_shift_the_locator` (`q,a\nok,\xd9\x85\nx\xff\n` split at every point, the BOM file at every
   point, and line 1002 at 1 MiB / 1000-byte chunks). windows-1256 decodes every byte, so it has no invalid-byte row.
   Faults C01 (the old offset cut), C02 (valid text dropped) and C03 (decoder state ignored) are RED.
2. **EXPECTED-SHA-MISMATCH-COMPLETES** — fixed. An `expected_sha256` that is not the hash the reader was declared with is
   `failed` / `source_changed` before a byte is read and before any record exists (`run_csv_import`, and the preview path).
   Test `test_an_expected_hash_other_than_the_readers_fails_before_a_record`; fault C04 RED.
3. **C4-MIDSTREAM-STOP-VACUOUS** — fixed in `tests/integration/test_ftf_0504_csv_import_postgres_s3.py`: the large dataset is
   now 16 MiB (under the ~18 MB at which SeaweedFS ends a slow stream itself), a control run with S3 left running must
   complete having read every byte, and the stop run must be `blocked/source_unavailable` having read fewer bytes than the
   control. A no-op stop fails the second assertion. Locally (real PG16 + an in-process S3 stand-in) the control passes and the
   stop cannot be emulated, as before; the real run is the CI job `csv-import-integration`.
4. **Evidence gaps** — size boundaries at the production constants (`test_size_boundaries_at_the_production_constants`: field
   exactly 2 MiB vs +1, mapped total exactly the cap vs +1, logical record cap), a time budget for a maximum-size field in
   1-byte chunks (`test_a_max_size_record_in_one_byte_chunks_stays_linear`: about 6 s, bound 120 s, and 7-byte chunks faster),
   every-split-point tables for documents of at most 4 KiB in all five encodings (two-piece and three-piece splits, one report
   each), wrong-declared-encoding rows for utf-8-sig and windows-1256, a unit test pinning `dataset_purpose` (fault C09), and
   the spec-matrix note rewritten (it described the removed round-1 catalog edit).
5. **Ruling: fatal locator in the report** — done. `import_common.py` gains one additive piece: `LocatedImportReport(ImportReport)`
   with `fatal_locator`, validated against the closed locator grammar, refused on a completed report, inside the digest.
   `ImportReport.fatal_locator` is a non-field class attribute (None), so `ImportReport.__dataclass_fields__`, a report's body
   and its digest are exactly what they were: golden digests for a completed and a failed report are pinned in
   `test_the_locator_lives_in_the_report_and_its_digest` and `tests/tasks/test_ftf_0502_p1.py` passes unedited. (A real field
   with a default would have put a `fatal_locator` key in `__dataclass_fields__`, which P1's REP-1 check forbids.)
   `CsvImportOutcome.fatal_locator` is removed; `run_csv_import` fills the report's. `ImportAccumulator.report()` takes the
   optional `fatal_locator`. Faults C05-C08 RED.
