## What the other session's four commits did

Round 2's scanner tracked strings and raw bracket depth over one whole-document text buffer. Round 3
replaces it with a byte-level grammar state machine fed chunk by chunk: for every open `{`/`[` it
tracks what the innermost container expects next (a key, a colon, a value, a comma or its closer)
and the position in the grammar (after `[`, after a comma, after a key, ...) — that is the whole JSON
grammar except a bare literal's own spelling and an escape's own validity, which `strict_loads` still
judges per element.

1. **WHOLE-DOCUMENT-BUFFERED** — fixed. Only the bytes of the *current* value are retained (bounded
   by `max_record_bytes`); nothing document-sized is ever held at once.
   `test_memory_ratio_between_sizes_is_within_one_and_a_half` pins the sibling-importer 1.5x
   contract directly; `test_memory_is_linear_not_quadratic` keeps the round-2 record-count check.
2. **EXPECTED-SHA-MISMATCH-COMPLETES** — fixed: the caller's `expected_sha256` is compared against
   the reader's own declared hash before a byte is read.
3. **STRUCTURE-ERRORS-NOT-FATAL** — fixed. Round 2's own real, reproduced defect
   (`[G, 1"]", G]` completing with the third element silently dropped, because raw bracket-depth
   tracking cannot tell a genuine close from one a stray quote shifted into) is closed by the new
   per-container expectation state, which makes every grammar error — a value starting with a
   character that cannot start a JSON value, a missing or doubled comma/colon, a `]` closing a `{`,
   an unclosed string/bracket, a trailing comma, content after the document's end, a scalar where
   the container should be — fatal `json_malformed` at its own real byte offset (not round 2's
   fixed `object:0` for every document-level failure). A value under an *ignored* top-level key is
   still parsed strictly and bounded by `max_record_bytes` — "ignored" is not "unchecked".
4. **OVERSIZE-ELEMENT-ENDS-IMPORT** — fixed: an oversize element is discarded as it arrives (its
   structure still tracked, so later elements are never mis-located) and becomes one
   `RowRejection record_too_large`; the import continues. No fatal tier.

Also: a UTF-8 BOM at byte 0 is now accepted and skipped (round 2 refused it as fatal). A container
pointer deeper than one token is `MappingUnsupportedError`/`mapping_unsupported` — already a shared
`import_common.py` catalog member (no catalog edit this round) — rather than folded into
`json_malformed`.

**INTEGRATION-MISSING** — closed: `tests/integration/test_ftf_0503_json_import_postgres_s3.py` (new)
+ CI job `json-import-integration` (new, wired into `ci-verdict`'s `needs`). Real PG16 as `sovra_app`
+ live SeaweedFS through the real FTF-0501 upload routes. The mid-stream S3 stop is proven against a
**control run**: a 16 MiB dataset (sized under SeaweedFS's own natural stream-truncation point) that
completes normally with S3 left running, so a no-op stop could not pass — closing the
C4-MIDSTREAM-STOP-VACUOUS class a sibling importer's own earlier round had to fix. Damaged-storage
cases are located by byte offset.
