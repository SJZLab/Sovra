## Design refinements over the QUEUE.md sketch (disclosed, not silent)

The QUEUE.md Backlog entry for this task is explicitly a sketch ("What to build (pure verifier)")
rather than a frozen contract — unlike a task with a `shared_contracts_read` OpenAPI/JSONSchema
file, this one has no existing frozen interface to violate, and the packet itself says "refine
any oversized item ... record exact files" before READY. Two concrete refinements, both load-bearing
for `verify_egress` to be a pure function:

1. `PlaintextInspection` and `PacketCaptureObservation` each carry their own `canary_found: bool`.
   The sketch leaves this implicit (relying on the ledger's own side-effecting
   `CanaryLeakedError`), but `verify_egress`'s own branching (and this module's own fault table)
   needs the same fact as plain data, not an exception a caller already caught several steps
   earlier. The ledger's own raise is still exercised directly and unmodified by
   `scan_store_for_canaries` and by `tests/tasks/test_ftf_0906.py`'s own scan tests — this is an
   addition, not a replacement.
2. `controlled_destination` is confirmed (per the sketch's own text) to never go through the
   ledger. A flow's own `canary_placements` (FTF-0905 `PlacementRecord`s) instead scope which
   *other* stores a canary may legitimately appear at for that flow; anything outside that scope
   is `canary_leaked`. In the real integration, every flow's `canary_placements` is empty — every
   log/artifact appearance is treated as a leak, which is the correct default and the one the
   negative_acceptance clause is actually testing.

integration harness), run and shown to change behaviour — never a text/regex self-check.

| # | Fault | Mechanism | RED evidence |

## Disclosed scope and gaps

- **UNWIRED.** No qualification runner calls this module yet — `proving_symbol` stays blank,
  same precedent as FTF-0901/0902/0905. A live caller is a separate, dependency-gated task.
- **`workflow_history` never exercised.** No Temporal workflow exists in this repository yet
  (same gap FTF-0905's own module docstring already discloses for its own producers). Every real
  report this task can currently produce is `partial`, never `passed` — by design, not a defect.
- **Process scope only.** Cluster/CNI-topology evidence (DNS, IPv6, cloud-metadata paths inside a
  real cluster, live Temporal histories) is FTF-H027's own job on top of this one, per the
  QUEUE.md design's own scope boundary. This module's `scope` field accepts `"cluster"` for a
  rendered-policy digest, but nothing in this round exercises that path with real cluster
  evidence.
- **Real integration covers four flows (two allow, two deny) plus one real bypass and one real
  log-leak**, not the full combinatorial sweep of every encoding × every store the QUEUE.md sketch
  lists. `scan_store_for_canaries`'s own encoding coverage (literal/base64/hex/url/fragmented) is
  proven exhaustively in the pure unit tests instead (`test_scan_finds_every_declared_encoding`),
  which is the right-sized split: the real sockets prove real enforcement/arrival/non-arrival: the
  pure tests prove the scanner's own encoding logic, each already following the FTF-0905 sibling's
  own established split between "real socket, light combinatorics" and "pure, full combinatorics."
- **TLS fixture skip path.** If `openssl`/`update-ca-certificates`/passwordless `sudo` are ever
  unavailable in a runner, the integration prints a disclosure and exits 0 rather than failing —
  the same convention `test_ftf_h005_route_attestation.py` already established. Confirmed present
  and exercised (not merely assumed) in this sandbox during this round.
