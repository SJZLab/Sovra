## What was built
- `workers/data/ooxml_safety.py` (public, pure): the FTF-0501 `inspect_xlsx` checks ported for the worker —
  end-of-archive totals read before `zipfile` allocates, 10,000-entry and 4 MiB-directory bounds, declared and
  counted decompressed bytes (`PartBudget`, `read_part_blocks`), traversal / absolute / backslash / casefold-
  duplicate names, encrypted entries and non-stored/deflate methods, and an expat parser that refuses any DOCTYPE
  in every encoding.
- `workers/data/xlsx_importer.py`: `xlsx_events` / `run_xlsx_import` / `XlsxLimits` / `XlsxAborted`. The source is
  spooled to one anonymous 0600 `TemporaryFile` while `ChunkReader` hashes it; `zipfile` opens it only after the
  byte count and sha256 matched. Values only: formula (`<f>`, shared, array, `t="str"`) cells reject their row
  (`formula_cell`), error cells reject (`cell_error_value`), the cached `<v>` is never used; macro carriers are
  `unsafe_workbook`; external links `external_link_present` (never fetched); OLE/CFB, strict OOXML, templates,
  non-zip `unsupported_workbook`. Explicit sheet (exact name) and header row; `header` / `index` / `letters` slots.
- `tests/tasks/test_ftf_0505.py` (no DB, no network), `tests/integration/test_ftf_0505_xlsx_import_postgres_s3.py`,
  CI step + additive job `xlsx-import-integration` (in `ci-verdict` needs; ci.yml diff is 45 insertions, 0 deletions).

## Disclosed
- A sheet named in the mapping that does not exist is fatal `mapping_column_missing`: the shared `FAILURE_CODES`
  catalog has no sheet-specific code and this task does not edit it. A Control-plane catalog addition would give
  it its own code.
- Per the task's own text an absolute relationship target is `unsafe_archive`. Some producers (older openpyxl)
  write absolute targets (`/xl/worksheets/sheet1.xml`) and would be refused; relaxing that to "absolute but
  inside the package" is a one-line Control-plane decision.
- Per the task's own text an External sheet relationship (including a plain hyperlink) is `external_link_present`.
- `n`, `b` and `d` cells keep their literal `<v>` text: no float conversion, no date-serial interpretation, so a
  date stored as a number imports as its serial number. The mapping / preview UI (FTF-H011) must show samples.
- The `header_row` offset counts non-blank rows, as for CSV; locators are the sheet row (`row:<n>`).
- No live import route calls the importer yet: `proving_symbol` stays blank; product-true stays 47/47.
- The Excel-4 macro sheet prefix (`xl/macrosheets/`) is refused as `unsafe_workbook` in addition to the parts the
  design names.
