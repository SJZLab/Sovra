## The return
Round 2/3 (`PR #670`) committed the denial audit directly on the caller's own `AuditContext.session`
-- the real session the caller's own `tenant_scoped_session` opened. On real Postgres (PG16 as
`sovra_app`) that commit ends the caller's transaction early:

1. `SET LOCAL app.current_organization_id` is scoped to the transaction; committing clears it. A
   **second** denial in the same session then tries to INSERT an `audit_events` row with no tenant
   context bound, which row-level security refuses -- a raw `ProgrammingError` (RLS), not the typed
   `ExternalProviderDeniedError`, and that second denial's own audit row is lost.
2. Every later read in that same session also sees 0 tenant rows (RLS default-deny with no context
   bound), not an error -- a silent blind spot.
3. Whatever the caller had not yet committed in that same session is committed as a side effect of
   the denial's own `.commit()`.

## Fix
`_deny` now dispatches on `isinstance(audit.session, Session)` (the real SQLAlchemy ORM session
class, imported for real rather than only under `TYPE_CHECKING`):

- **Real session** (the only path any live caller will ever take): `_audit_denial_independently`
  reads (never writes) the caller's own currently-bound tenant context via
  `current_setting('app.current_organization_id', true)` under `session.no_autoflush` (so reading it
  can never flush the caller's own pending work), opens a **new** `Session` bound to the same engine
  (`audit.session.get_bind()`), binds that same tenant context to the new session via the existing
  `set_tenant_context`, writes and commits the audit event there, and closes it. The caller's own
  session is never committed, rolled back or flushed by this path. Binding the *caller's own* tenant
  context (not `audit.organization_id`) to the independent session preserves the existing
  cross-tenant protection unchanged: a denial whose `AuditContext.organization_id` disagrees with
  the caller's real bound tenant still gets refused by RLS on the INSERT, exactly as round 2/3's
  design did by reusing the same connection. A session with no tenant context bound at all (never
  opened through `tenant_scoped_session`) is refused with `external_provider_invalid_request`, not a
  crash.
- **Non-Session test double** (the existing unit-test fakes, which exist to exercise the pure
  decision logic, not real transactional isolation): unchanged -- written and committed in place, as
  round 1-3 always did. There is no real transaction there to corrupt.
