## P (read, hypothesize, no changes)

Read all four production files and their round-1 test files before changing anything:

- `model_catalog_ui.tsx` (FTF-0214): `readErrorDetail` has no `locale` parameter at all and
  returns a raw English template string -- the one place in this area that never got the
  bilingual pass. `handleLoadCatalog` accepts any 200 body with `Array.isArray(body.entries)`
  as its only check; `Object.entries(catalog.model_groups.entries)` then throws if
  `model_groups.entries` is anything but a plain object (a `{}` 200 sets `model_groups: undefined`
  so that specific path doesn't crash, but a 200 with `model_groups: {state, entries: null}` does).
  No native `<button>`/`<select>` sets a minimum target size. A successful load with zero entries
  renders a bare `<ul>`.
- `costprofile_schema_ui.tsx` (FTF-1301): `refresh()` does `setSearch(await response.json())` with
  **no shape check at all** -- the most direct Law 17 violation in this round. Same missing
  target-size/empty-state/overflow pattern.
- `model_to_artifact_mapping_ui.tsx` (FTF-0308): the `confirm-change` `role="alertdialog"` has
  `onClick={() => setPending(null)}` on Cancel and nothing on open -- no `queueMicrotask`/`focus()`
  anywhere, unlike its sibling `model_catalog_ui.tsx`'s probe-confirm (which already got this fix
  in the internal round-2 pass) and `mandate_editor_and_conflict_resolution_ui.tsx`'s own
  discard-confirm. `handleLoadArtifacts`/`handleLoadChanges` accept any array with no per-item
  check -- `ArtifactDetails`'s `packages.join(", ")` throws if `required_python_packages` is a
  string (a realistic backend-contract-violation shape), with no error boundary anywhere in this
  tree.
- `capability_compatibility_ui.tsx` (FTF-0309): already strictly validated (`isCapabilities`) and
  already fully bilingual -- no new behavioural defect specific to this file, only the two
  cross-cutting issues (target size, long-value overflow).
