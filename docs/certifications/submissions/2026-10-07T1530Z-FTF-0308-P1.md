## What shipped
- Migration `0022_model_catalog_entries` (revision id 26 chars): UQ (organization_id, id) on `litellm_connections` (the one on `trainable_artifacts` already exists from 0009); `model_catalog_entries` (composite FKs to connections and artifacts RESTRICT, UQ (connection, name), CHECK name <> '' and version >= 1; SELECT/INSERT/UPDATE for `sovra_app`, never DELETE); append-only `model_catalog_mapping_changes` (CHECK new = previous + 1; SELECT/INSERT only). Both tables ENABLE + FORCE RLS, `tenant_isolation` policy scoped to `app.current_organization_id`. No metadata/cost/supports_* columns (Law 11).
- `apps/api/app/litellm/model_catalog_mapping_store.py`: `set_training_artifact_mapping`, `require_current_mapping` (raises `MappingChangedError`), `list_mapping_changes`, `get_entry`. First mapping creates the entry at v1 (change row 0→1); each change bumps by exactly one, inserts one change row and writes audit `model_catalog_entry.training_artifact_mapping_change` in one transaction; same artifact is a no-op.
- `apps/api/app/litellm/model_catalog_mapping_routes.py`, mounted in `main.py`: GET / POST `.../models/{model_name:path}/training-artifact` and GET `.../training-artifact/changes`. POST runs a fresh `discover_models` before any write: non-`discovered` → 503 `gateway_unavailable`, alias not listed → 409 `model_not_accessible`. Errors 400/401/403/404 `not_found`/409 (`connection_revoked`, `model_not_accessible`, `artifact_not_ready`, `catalog_version_conflict`)/503.
- Contract frozen in `packages/contracts/openapi/03-interface.yaml` (three paths, closed request body).
- CI (additive only): job `model-catalog-mapping-integration`, its `ci-verdict` needs entry, and a gate step for `tests/tasks/test_ftf_0308_p1.py`.
- Not touched: `model_catalog_routes.py`, `training_capability_classifier.py`, the LiteLLM management API. No alias→artifact heuristic exists (a test greps for it and another asserts the store receives exactly the caller's artifact id).
