## PR #968's verdict → this round's fix, one to one

1. **Cross-tenant workspace add** ("the store adds a member to an Argilla workspace before the database
   check, so an org1 annotator can read org2's dataset") → `_require_current_scope`
   (`argilla_identity_store.py:398`): re-fetches the `argilla_review_scopes` row by `scope.id` under
   `organization_id`'s own RLS scope and confirms `argilla_workspace_id` matches, called from
   `sync_workspace_membership` (`:469`) in the SAME initial tenant-scoped session as the existing identity
   check, before any real Argilla network call. A `scope` naming a foreign or non-existent row is refused
   with `ArgillaIdentityError` up front — symmetric with the stale-identity-reference guard that already
   existed.
2. **Revoke/sync race** ("a revoked identity keeps workspace access") → the plain read-then-write
   INSERT/UPDATE in `sync_workspace_membership`'s entitled branch is replaced with one atomic,
   identity-liveness-guarded UPSERT (`:471-501`):
   ```sql
   INSERT INTO argilla_workspace_members (organization_id, scope_id, identity_id, status)
   SELECT :org, :scope, :identity, 'active'
   WHERE EXISTS (SELECT 1 FROM argilla_reviewer_identities
                 WHERE id = :identity AND organization_id = :org AND status = 'active')
   ON CONFLICT (scope_id, identity_id) DO UPDATE
   SET status = 'active', updated_at = now()
   WHERE EXISTS (SELECT 1 FROM argilla_reviewer_identities
                 WHERE id = :identity AND organization_id = :org AND status = 'active')
   RETURNING id
   ```
   If a concurrent `revoke_reviewer_identity` lands in the window between the pre-call check and the real
   `client.add_workspace_user` call (which takes real wall-clock time), the `EXISTS` guard fails at write
   time and `written` comes back `None`; the function then calls `client.remove_workspace_user` to undo the
   real Argilla-side add it just made, and raises `ReviewerIdentityRevokedError` — never leaving a revoked
   identity with real external access.
3. **Concurrent `sync_workspace_membership` raises IntegrityError** → the same atomic UPSERT above resolves
   this for free: a concurrent winner's own INSERT no longer raises `IntegrityError` on the loser's side,
   it falls through to `ON CONFLICT ... DO UPDATE`.
4. **Table-wide UPDATE grant lets a revoked identity be restored** → new migration
   `0035_argilla_identity_hardening.py`: `argilla_review_scopes` loses `UPDATE` entirely (nothing ever
   updates it); `argilla_reviewer_identities` keeps `UPDATE` on exactly `(status, revoked_at, updated_at)`;
   `argilla_workspace_members` keeps `UPDATE` on exactly `(status, updated_at)`; a `BEFORE UPDATE` trigger on
   `argilla_reviewer_identities` refuses ANY update once `OLD.status = 'revoked'` (the same "terminal state,
   no further change is allowed" convention `0028_model_import_state_machine.py`'s own job-state trigger
   already uses). `revoke_reviewer_identity`'s own final UPDATE gained `AND status <> 'revoked'` so a
   legitimate concurrent double-revoke affects zero rows instead of ever reaching the trigger.
5. **Law 17 outage paths have no test** → `test_sync_membership_outage_on_add_is_never_swallowed` and
   `test_sync_membership_outage_on_remove_is_never_swallowed` (unit); confirmed the production code already
   propagated `ArgillaUnavailableError` correctly without a code change — these were a coverage gap, not a
   production bug.
6. **Never approved for omission: the real-Argilla CI job, the R002 `/validate` test, the compose stack and
   a gate step** → new CI job `argilla-real-server-integration` (`.github/workflows/ci.yml`), new test
   `tests/integration/test_argilla_real_server.py`, wired into `ci-verdict`'s `needs:`. See "Real-Argilla CI
   job" below — this is the one piece of this round's evidence that has not yet run for real.

Also fixed: the fake test double (`tests/tasks/argilla_test_support.py`) now checks the real
