## What the return found

Round 5's own `_F5_BENIGN_COLLIDING_SPLITS` table (25 hand-picked rows) was meant to exercise
every `_BENIGN_NAMES` word that collides with a credential ending when split at a `_ - .`
separator, but it missed 7 of the 32 `_BENIGN_NAMES` words that actually end in one of
`_NAME_SUFFIXES`: every "-state" word (`estate`, `realestate`, `upstate`, `restate`) plus
`compass`, `jockey` and `qrcode`. Because the automated mutation-gate's generic operators only
need ONE surviving input to kill a global code change, round 5's existing `key`/`code`/`pass`/
`session` rows already killed the *generic* AST mutants on the segment-lookup lines — but two
*specific*, hand-crafted narrowings of the same lookup (dropping `"state"`; restricting the set
to only `key`/`code`/`pass`/`session`) were never exercised by any row, because no row in the
table ever needed `"state"` to pass. Both leak `up_StAtE=<secret>` / `re_StAtE=<secret>`: line
318's camel split defeats the last-word check (`"StAtE"` → `"St"`+`"AtE"`), and the deny-by-default
fallback then wrongly excuses `"upstate"`/`"restate"` as benign.
